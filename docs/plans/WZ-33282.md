# WZ-33282 — [AgentOS] FE - Medley AgentOS UI for dev experience

- Jira: https://whoz.atlassian.net/browse/WZ-33282 (User Story, parent epic WZ-28664 "FP - Coday Convergence - Feb 2027")
- Type: user story, not a bug
- Work branch: `feature/WZ-33282-agentos-ui-dev-experience`, cut from `origin/workstream/forge/master` (44e47400), which is the base of this worktree
- Chosen route: **frontend** only

## Expected outcome

In the AgentOS settings UI, developers can see that the prompt parameter "Default value" is mandatory, can edit an agent's
instructions in a larger textarea or in full screen, and cannot save agent instructions longer than 20,000 characters.

## Acceptance criteria

From the ticket description (the only comment is a Slack link with no extra requirement):

1. **AC1 — Prompt "Default value" is flagged as mandatory.** In the prompt form, each parameter's "Default value" label shows the
   same `*` required marker as "Name".
2. **AC2 — Bigger agent prompt editor.** The agent config "Instructions" textarea is taller than today (6 rows) and uses the full
   width of the form.
3. **AC3 — Full-screen option.** A button next to the "Instructions" field opens the textarea in a full-screen editor and closes it
   again. The text, the validation and the value sent on save are the same in both modes.
4. **AC4 — 20k limit.** The form refuses to save agent instructions longer than 20,000 characters: the Save button is disabled and an
   error message is shown under the field.

Criteria I derived myself (flagged):

- **AC1b (derived)** — a touched, empty "Default value" shows the message "Default value is required.", like the parameter name does.
  The validator already exists, so only the message is new.
- **AC3b (derived)** — the full-screen editor closes with the Escape key and with the same toggle button. Keyboard focus stays in the
  textarea when the mode changes.
- **AC4b (derived)** — a character counter (`n / 20,000`) is shown under the field, so the limit is visible before it is reached.
- **AC4c (derived, confirmed by the user)** — the 20,000 limit is a **frontend constant**. It mirrors a limit that the ticket places in
  "the BE", which is not the AgentOS service of this repository (see the Location clues). No AgentOS API change.

Patterns to follow:

- Validation lives in the reactive form (`Validators.*`), the template only shows the message through `[error]` of `ds-form-field`
  (same as "Name" in the prompt form, and as `delegationTimeoutControl` in the agent form).
- UI state is a `signal` (the components are `OnPush`).
- The "Save" button is already `[disabled]="form.invalid || isSubmitting()"` and `submit()` returns early on `form.invalid`: a validator
  on the control is enough to block the save, nothing else to wire.
- Limits mirrored from a backend are named constants with a comment (e.g. `MAX_NAME_LENGTH` in `user-group-form.component.ts`).

Recent history and regression areas: `agent-config-form` is a hot file (model select, sub-agents, skills, built-ins in the last
changes). The spec covers the payload shape of `submit()`: the change must not touch `buildIntegrationsPayload`,
`buildSubAgentsPayload`, `buildSkillSelectorsPayload` or the payload object, apart from nothing at all (the instructions value sent stays
`instructionsControl.value?.trim() || undefined`).

## Scoped change (frontend only)

### 1. `libs/agentos-ui/src/lib/components/prompt-form/prompt-form.component.html` (AC1, AC1b)

On the parameter "Default value" `ds-form-field`, add `required` and an `[error]` binding modelled on the parameter name:

```html
<ds-form-field
  label="Default value"
  [controlId]="'param-default-' + $index"
  required
  [error]="group.controls['defaultValue'].invalid && group.controls['defaultValue'].touched ? 'Default value is required.' : null"
>
```

Optionally align the doc comment of `prompt-form.component.ts` (it still says "optional defaultValue (null = required at execution
time)", which contradicts both the validator and `PromptParameterDto.defaultValue` `@NotBlank`): replace with "required defaultValue".
Comment only.

### 2. `libs/agentos-ui/src/lib/components/agent-config-form/agent-config-form.component.ts` (AC2–AC4)

- Add an exported constant next to the component:
  `export const MAX_INSTRUCTIONS_LENGTH = 20_000` with a comment: mirrors the limit enforced by the consumer backend (Medley), the
  AgentOS API itself has none; to keep in sync by hand.
- `instructions: new FormControl<string | null>(null, { validators: [Validators.maxLength(MAX_INSTRUCTIONS_LENGTH)] })`.
  The validator applies to the raw value (what the user sees in the counter). Keep it that simple.
- Expose `protected readonly maxInstructionsLength = MAX_INSTRUCTIONS_LENGTH`.
- A signal of the current length, bridged like `executionModeValue`:
  `toSignal(this.form.controls.instructions.valueChanges, { initialValue: ... })` then
  `instructionsLength = computed(() => (value ?? '').length)`. Note: `setValue` in edit-mode hydration emits `valueChanges`, so the
  counter is right after load.
- `protected readonly instructionsFullscreen = signal(false)` and `toggleInstructionsFullscreen()`. Close on Escape with a
  `(keydown.escape)` handler on the textarea (or on the wrapper) that only acts while full screen. No global listener, no new service,
  no dialog/CDK overlay dependency.
- Add `styleUrl: './agent-config-form.component.scss'` to the decorator.

### 3. `libs/agentos-ui/src/lib/components/agent-config-form/agent-config-form.component.html` (AC2–AC4)

Replace the "Instructions" field with:

- A wrapper `<div class="agent-config-instructions" [class.agent-config-instructions--fullscreen]="instructionsFullscreen()">`
  around the `ds-form-field`.
- `ds-form-field`: keep `label="Instructions"` and `controlId`; add
  `hintId="agent-config-instructions-hint"`, `[hint]="instructionsLength() + ' / ' + (maxInstructionsLength | number) + ' characters'"`
  (or a preformatted string from the component, to avoid importing `DecimalPipe`), `errorId="agent-config-instructions-error"`,
  `[error]="instructionsControl.hasError('maxlength') ? 'Instructions must not exceed 20,000 characters (currently ' + n + ').' : null"`.
  The error is shown as soon as the limit is exceeded (not only when touched): the user is typing in it.
- The textarea: `rows="20"` (was 6), `aria-describedby="agent-config-instructions-hint agent-config-instructions-error"`,
  `[attr.aria-invalid]="instructionsControl.invalid"`, `(keydown.escape)="..."`. Do **not** set the native `maxlength` attribute: it
  would silently truncate a paste instead of showing the error required by AC4.
- A ghost button inside the wrapper, before or after the textarea:
  `<button dsButton variant="ghost" type="button" [attr.aria-pressed]="instructionsFullscreen()" (click)="toggleInstructionsFullscreen()">`
  labelled "Full screen" / "Exit full screen". `type="button"` is mandatory so it never submits the form.
- The same textarea element is kept in both modes (only CSS changes), so the `FormControl` binding, the value and the caret are
  preserved and there is no duplicated control.

### 4. `libs/agentos-ui/src/lib/components/agent-config-form/agent-config-form.component.scss` (new, AC2–AC3)

Component-scoped styles only, tokens only (no new colour):

- `.agent-config-instructions textarea { min-height: 24rem; }` (bigger by default; width is already 100% via `.ds-control`).
- `.agent-config-instructions--fullscreen { position: fixed; inset: 0; z-index: <above the app shell>; display: flex; flex-direction:
  column; gap: .5rem; padding: 1.5rem; background: var(--color-bg, #fff); }` and its textarea `flex: 1; min-height: 0; resize: none;`.
  `ds-form-field` inside it must grow (`flex: 1; display: flex; flex-direction: column`), which may need `:host ::ng-deep` or a
  `ds-form-field` with `grow` — implementer's choice, keep it within this file.

Nothing in `libs/design-system`: a full-screen editor is a single use, promoting it to the design system would be premature.

### Out of scope (proposed separate tickets)

- Enforcing the instructions limit in the AgentOS API itself (`@Size(max = …)` on `AgentConfigDto.instructions`, or a
  `maxInstructionsLength` served by `/api/agent-configs/defaults` so the frontend reads it instead of hard-coding it). Today the
  frontend constant can drift from the consumer backend.
- Same size/full-screen treatment for prompt content entries and skill bodies.
- A reusable full-screen textarea component in the design system, if a second use appears.

## Risk level

**Low.** Template, one validator, one signal and a component stylesheet, in two forms. No API, no payload, no shared component
change. The only behavioural restriction is new: an agent whose stored instructions already exceed 20,000 characters can no longer be
saved from this form until they are shortened, which is the requested behaviour.
