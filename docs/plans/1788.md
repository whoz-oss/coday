# #1788 — Ask for an explicit validation before leaving with a prompt not sent

Ticket: https://github.com/whoz-oss/coday/issues/1788. It is a GitHub issue with a title only ("If use as a prompt not sent ask for explicit validation when closing tab/changing page"): empty body, no comments, no linked ticket. There is no Jira ticket to transition.
Work branch: `work/forge/1788-warn-unsent-prompt-on-leave`. Base and PR target: `workstream/forge/master` (forge workstream).
Type: **improvement** (data-loss prevention). Frontend, plus a few lines in the Electron main process of the desktop app.

## 1. Expected outcome

When the user has typed a prompt in a composer and has not sent it, leaving the screen asks for an explicit confirmation first. This covers closing or reloading the tab, and in-app navigation that would drop the draft. Without a draft, nothing changes: no prompt, no delay.

- **Observed:** a draft typed in the home composer (`CaseHomeComponent`) or in the reply composer of a case (`CaseChatComponent`) is lost without warning when the user closes or reloads the tab, opens another case, starts a new case, switches namespace or opens a settings page. The draft lives only in the `inputValue` signal of the component. `CaseChatComponent.reinitialise()` resets it to `''` on a case switch, and `CaseHomeComponent` resets it on a namespace or parent change.
- **Expected:** in all these cases, if the draft is not blank, a confirmation appears. Cancelling keeps the user on the screen with the draft intact. Confirming proceeds and discards the draft, as today.
- **Reproduction:** complete from the title and the code. Type text in either composer, then close the tab or click another case in the sidebar.

## 2. Acceptance criteria

The ticket body is empty, so these are derived by the architect from its title:

1. **Tab close / reload / external URL (title):** with a non-blank draft in a mounted composer, the browser shows its native "Leave site?" dialog (`beforeunload`). Without a draft, no dialog.
2. **In-app page change (title):** with a non-blank draft, every router navigation that leaves or changes the case shell (another case, New case, Create sub-case, namespace switch, settings/profile pages, Back to parent case, browser Back/Forward) first asks `window.confirm('You have a prompt that has not been sent. Leave this page and discard it?')`.
   - Cancel → the navigation is cancelled, the URL stays the same, and the draft and the composer are untouched.
   - OK → the navigation proceeds, as today.
3. **Sending is not leaving:** a successful send, from the home composer (which navigates to the new case) or from the case chat, never asks, because the draft is cleared before the navigation. The same holds for a voice message sent from home (its composer is empty by construction).
4. **Blank is not a draft:** whitespace only does not count (same `trim()` rule as `canSend`).
5. **Desktop app (derived, regression protection):** in the Electron app, a `beforeunload` that is prevented must never block a quit, reload (Cmd+R/F5) or window close silently. A native dialog "Leave / Stay" is shown instead.
6. Nothing else changes: send rules, autocomplete, attachments, the message editor of a bubble, and the factory-cockpit guard.

## 4. Analysis (why nothing protects the draft today)

- `libs/agentos-ui/src/lib/agentos.routes.ts`: the `home` route (`CaseShellComponent`) has only `canActivate: [agentosReadyGuard]`. It has no `canDeactivate`, and nothing in `libs/agentos-ui` listens to `beforeunload`.
- Every navigation inside the case section is a **query param change on the same route** (`router.navigate(['/agentos/home'], { queryParams: … })` in `case-shell.component.ts`, `case-home.component.ts`). With the default `runGuardsAndResolvers: 'paramsChange'`, Angular would **not** run a `canDeactivate` on such a navigation. The route therefore needs `runGuardsAndResolvers: 'paramsOrQueryParamsChange'`.
- The draft is private to two sibling components that the shell swaps with `@if (activeCaseId())`. A guard on the shell route cannot read it directly. A small root service that the composers register with is the least coupled bridge: the shell does not need to know about composers.
- Desktop: `libs/desktop-core/src/lib/window-manager.ts` creates the main `BrowserWindow`. In Electron, a prevented `beforeunload` cancels the unload **without any UI** unless `webContents` handles `will-prevent-unload`. Without that handler, criterion 1 would make Quit, Cmd+R (which `before-input-event` turns into `loadURL`) and window close silently do nothing while a draft exists.

## 6. Scoped change

### Frontend (`libs/agentos-ui`)

**6.1 New `libs/agentos-ui/src/lib/services/unsent-draft.service.ts`** (`@Injectable({ providedIn: 'root' })`, about 40 lines):

```ts
/** Composers with a prompt the user typed and has not sent, so that leaving asks first (#1788). */
export class UnsentDraftService {
  private readonly drafts = new Set<Signal<boolean>>()
  /** Registers a composer's "has an unsent draft" signal for the lifetime of [destroyRef]. */
  register(hasDraft: Signal<boolean>, destroyRef: DestroyRef): void   // add, and delete onDestroy
  hasUnsentDraft(): boolean                                           // some registered signal is true
  /** True when leaving may proceed: no draft, or the user confirmed discarding it. */
  confirmDiscard(): boolean   // !hasUnsentDraft() || window.confirm(UNSENT_DRAFT_MESSAGE)
}
export const UNSENT_DRAFT_MESSAGE = 'You have a prompt that has not been sent. Leave this page and discard it?'
```

In its constructor, add **one** `beforeunload` listener on `inject(DOCUMENT).defaultView`, removed through `inject(DestroyRef).onDestroy`: `if (this.hasUnsentDraft()) { event.preventDefault(); event.returnValue = '' }`. The `returnValue` line is the legacy requirement of Chromium/Electron. Browsers show their own text: a custom message is ignored.

**6.2 New `libs/agentos-ui/src/lib/guards/unsent-draft.guard.ts`:**

```ts
/** Asks before a navigation drops a prompt that was not sent. */
export const unsentDraftGuard: CanDeactivateFn<unknown> = () => inject(UnsentDraftService).confirmDiscard()
```

**6.3 `agentos.routes.ts`, `home` route only:** add `canDeactivate: [unsentDraftGuard]` and `runGuardsAndResolvers: 'paramsOrQueryParamsChange'`, with a one-line comment: case, new case and namespace changes are query param navigations on this route. `agentosReadyGuard` is then re-run on each of them, but it caches its first wait (`firstWait ??=`), so it resolves at once. Do not add the guard to the settings routes: they have no composer.

**6.4 `case-home.component.ts`:** in the constructor, register
`inject(UnsentDraftService).register(computed(() => !!this.inputValue().trim()), this.destroyRef)`.
Add no other change. `submit()` already does `this.inputValue.set('')` before `router.navigate`, and a voice message requires an empty text (`canRecord`). Do **not** guard `returnToParent()` here: the route guard covers it.

**6.5 `case-chat.component.ts`:** the same registration in the constructor, with the same `computed` on `this.inputValue`. Add no other change. A successful `submit()` clears the text and does not navigate. `reinitialise()` runs only after the router has accepted the navigation, which means after the confirmation.

Do not count staged attachments, referenced files or an open bubble editor as a draft: that is out of scope (see below).

### Desktop (Electron main process, `libs/desktop-core`, non-browser code)

**6.6 `window-manager.ts`, `createMainWindow`:** after the `before-input-event` handler, add:

```ts
// The page asks before dropping an unsent prompt (beforeunload): Electron shows nothing by itself, so ask here.
win.webContents.on('will-prevent-unload', (event) => {
  const { dialog } = require('electron') as typeof import('electron')
  const choice = dialog.showMessageBoxSync(win, {
    type: 'question', buttons: ['Leave', 'Stay'], defaultId: 1, cancelId: 1,
    message: 'Leave this page?', detail: 'A prompt you typed has not been sent. It will be lost.',
  })
  if (choice === 0) event.preventDefault() // preventDefault here means: ignore beforeunload, unload anyway
})
```

Note: on macOS, a plain window close only hides the window (existing `close` handler), so the page is not unloaded and nothing is asked. That is correct, since the draft survives.

### Contract between the sides

There is no HTTP contract and no backend change. The only cross-side contract is the browser event: the page cancels `beforeunload` (`preventDefault` + `returnValue = ''`) when a draft exists, and the Electron main process turns the resulting `will-prevent-unload` into a native Leave/Stay dialog. **Order:** 6.1 → 6.2 → 6.3 → 6.4 → 6.5 → specs → 6.6.

### Out of scope (propose separate tickets if wanted)

- Treating staged attachments, referenced files, or a bubble being edited (`agentos-message-editor`) as unsent work.
- Keeping the draft across navigation (a per-case draft store) instead of asking. That is a better UX, but a product decision.
- Replacing `window.confirm` by the design-system `ds-confirm-dialog` (needs an async guard bridge).

## 7. Verification criteria

Tests to add (Jest, project `agentos-ui`):

- `services/unsent-draft.service.spec.ts`:
  - With no registration, `hasUnsentDraft()` is false and `confirmDiscard()` is true **without** calling `window.confirm`.
  - With a registered `signal(true)`: `confirmDiscard()` returns what a mocked `window.confirm` returns (false, then true), with `UNSENT_DRAFT_MESSAGE`.
  - `window.dispatchEvent(new Event('beforeunload', { cancelable: true }))` is `defaultPrevented` with a draft, and not without one (same technique as `workflow-detail-page.component.spec.ts`).
  - After the `DestroyRef` of the registration is destroyed, the draft no longer counts.
- `guards/unsent-draft.guard.spec.ts`: the guard returns the result of `confirmDiscard()` (run through `TestBed.runInInjectionContext`).
- An assertion (in the guard spec or a small `agentos.routes.spec.ts`) that the `home` route has `canDeactivate` containing `unsentDraftGuard` and `runGuardsAndResolvers: 'paramsOrQueryParamsChange'`. **This is the regression case:** before the change, nothing guards the route.
- `case-home.component.spec.ts`: typing (`inputValue.set('hello')`) makes `UnsentDraftService.hasUnsentDraft()` true, `'   '` keeps it false, and after a successful `submit()` it is false **before** `router.navigate` is called (check inside the navigate mock).
- `case-chat.component.spec.ts`: typing → true. After a successful `submit()` → false.

Existing checks that must stay green:

- `pnpm nx run-many -t lint test -p agentos-ui desktop-core` (in particular `case-home`, `case-chat`, `case-shell` and `agentos-ready.guard` specs).
- `pnpm nx run-many -t build -p client desktop`.
- `apps/client-e2e/src/composer-scroll.spec.ts`: it fills drafts but never navigates away, so it stays green. If Playwright reports a pending `beforeunload` on page close, add `page.on('dialog', d => d.accept())` there. That is an acceptable test-only adjustment.

Manual checks (`pnpm web:serve:dev`, then `pnpm nx run web:local -- --managed` or the desktop app for 6.6):

- Type in the home composer, then close or reload the tab → the native dialog. Stay keeps the text.
- Type in a case reply, then click another case, New case, the namespace picker, Settings, or browser Back → the confirm. Cancel keeps the URL, the case and the text. OK switches and the text is gone, as today.
- Send from home (text and voice) and from a case → no prompt.
- An empty or whitespace-only composer → no prompt anywhere.
- Delete the active case with a draft in its reply → the confirm appears, which is acceptable: cancelling leaves the user on the removed case, whose composer is closed.
- Desktop: with a draft, Cmd+R and Quit show "Leave / Stay". Stay keeps the app, Leave proceeds. Without a draft, nothing is shown.

**Risk level: medium-low.** The change is additive (one root service, one guard, two one-line registrations, a route option, an Electron handler). The real risks are three, and the tests or manual checks above cover each one: (a) `runGuardsAndResolvers` makes guards run on every query param navigation of the shell, (b) a prompt on a navigation the app itself triggers after a send, prevented by the clearing order, and (c) Electron silently blocking quit, prevented by 6.6.
