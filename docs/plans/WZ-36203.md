# WZ-36203 — Wizz on completed agent responses

## Outcome, classification and clarification

Add an accessible, default-off Wizz button that briefly animates only the conversation messages panel when an observed live agent response finishes, without animating history or disturbing scroll and final layout.

Ticket: https://whoz.atlassian.net/browse/WZ-36203

Classification: User Story / feature, not a bug. Observed-versus-expected bug behaviour, reproduction completeness and a root cause are not applicable. Jira has no comments, attachments, issue links or remote links at inspection. The current explicit execution request supersedes the ticket's original backlog/no-Factory scheduling note for this run only.

**Reporter-approved clarification in this session:** prefer missing an effect over a false Wizz on history. Require ThinkingEvent or TextChunkEvent, then a NEW agent MessageEvent, then AgentFinishedEvent on the same uninterrupted connection. Some replies without transient evidence or spanning reconnection will intentionally not animate. This narrows exhaustive response coverage explicitly, not through an undocumented timing heuristic.

## Acceptance criteria

From the ticket:

1. Wizz button in conversation toggles the effect, off by default, visibly active when enabled.
2. New completed agent responses briefly shake only the conversation panel, not the page.
3. One effect per finished response, not per chunk, user message, tool call or technical event; history loading never triggers it.
4. No effect-induced scroll or final layout change.
5. With prefers-reduced-motion, show a brief stationary highlight instead of shaking.
6. Accessible label, native keyboard operation and exposed enabled/disabled state; follow visual and language conventions.
7. Frontend only: no sound, dependency, persistence, backend or engine change. Reuse the existing completion signal.
8. Add frontend tests for toggling, unique completion, intermediate/history exclusion and reduced motion; visually verify layout/scroll.

Derived design decisions (not original ticket wording): reset the toggle off on case switch/reopen/recreation; enabling never replays a prior completion; disabling cancels an active effect. Consume completion candidates even while disabled. Require non-empty agent text and matching message actor.id / finishing agentId. Suppress unsafe or ambiguous ordering/identity rather than guessing.

## Minimal scoped implementation

### Frontend route

1. **New `libs/agentos-ui/src/lib/components/case-chat/wizz-response-tracker.ts`**: small pure component-owned tracker, no global service/event bus. Consume only first-seen current-case events. Record transient live evidence, then non-empty AGENT message actor identity, and yield a qualifying completion only on matching AgentFinishedEvent. Consume/reset on every finish whether enabled or not. Multiple chunks/messages in one run produce one effect. Reset candidates on Selected/Running turn replacement, USER Message/Answer, terminal/error boundaries and explicit connection reset. Normalise UUID casing for comparisons. No timestamp threshold or browser/server clock heuristic. Technical/tool events alone never qualify; preserve evidence through normal tool iterations until a turn boundary.
2. **`case-chat.component.ts`**: local default-off enabled signal, tracker and finite effect state. Feed the tracker after existing dedup and before per-type early returns, without changing existing event handling. Test enabled only when a qualifying completion arrives. Reset pending detection on transport error/open (including automatic reconnect), retry, navigation/reopen and destroy. Open resets; it is not a declaration that following durable frames are live. Capture source/case generation and ignore obsolete callbacks. Cancel animation/timers on disable and connection/lifecycle reset. Navigation/reopen also set enabled false. Reliably restart overlapping effects using alternating animation names or explicit render-boundary restart, without rebuilding messages DOM. Use cancelable finite cleanup guarded against stale callbacks. No Wizz scroll/focus calls, API/storage writes, new EventSource or timeline mutation.
3. **`case-chat.component.html`**: native type=button with visible Wizz label, accessible explanatory name/title, aria-pressed binding, active and focus-visible styles. Available during generation. Apply effect classes only to messages-region. Keep toggle reachable at narrow widths without opportunistic header redesign.
4. **`case-chat.component.scss`**: short horizontal transform-only shake, about 3px/350ms, starting/ending at rest with no retained transform. Reduced-motion media query replaces shake with geometry-neutral stationary inset highlight; explicitly no movement. Use theme tokens, no final dimensions/margins/padding/layout changes. Verify transforms do not introduce ancestor scrolling.
5. **New `libs/agentos-ui/src/lib/components/case-chat/wizz-response-tracker.spec.ts`**: pure ordering/identity/role/reset/candidate-consumption tests.
6. **`case-chat.component.spec.ts`**: extend fake-stream tests for gating, dedup, replay, reconnect open/error, retry, stale callbacks, navigation/reopen/destruction, animation restart and timer cancellation.
7. **New `apps/client-e2e/src/wizz.spec.ts`**: controlled case-stream dispatch using composer-scroll's isolated API mock pattern, real toggle semantics/keyboard/reduced-motion and geometry checks. No shared test-harness refactor needed.

### Backend and API contract

No backend change; select **frontend only**. Keep the existing endpoint, `case-event` channel, JSON event types, stable ids and ordering unchanged. No new DTOs/generated-client changes or cross-route ordering dependency. Current-case first-seen events flow into the local tracker; only its qualifying completion result may start the decorative effect.

## Verification and regression risk

Risk **medium**: small visual feature inside a large frequently changed component with subtle replay/reconnection semantics.

Automated coverage required:

- Default off; click/Enter/Space toggle, accessible name/aria-pressed/active styling; no persistence or new API writes. Off again after navigation/reopen/recreation.
- Enabled Running → Thinking → many chunks → non-empty agent Message → matching Finished triggers once, never before finish. Thinking plus message without chunks also qualifies.
- Multiple messages in a turn: one effect. Two eligible turns including overlapping animation restart correctly and return to rest.
- Disabled completions, user/system/empty messages, mismatched identity, tools/technical events alone, IDLE without finish, duplicate completion and repeated chunks do not trigger.
- Slow initial history while user enables Wizz, unseen durable replay on retry/reconnect, and replayed completion before buffered evidence never animate. Evidence cannot leak across turn boundaries into an unrelated reply. Lost/no transient evidence intentionally suppresses the effect (approved).
- Reset on error/open/retry/terminal/case switch/destroy, stale sources and stale timers cannot animate the next case.
- Browser prefers-reduced-motion emulation: visible highlight with no moving transform. Normal mode moves messages region only.
- Long-history browser test scrolled away from bottom: compare scrollTop, scrollHeight/client sizes and header/composer/sidebar/drawer bounds before/during/after. Compare identical appended replies with Wizz off and on, distinguishing normal new-content behaviour from effect-induced scrolling. Check magnetic-bottom behaviour, narrow/mobile and short windows, open drawer, focus/selection and final geometry.

Existing case-chat dedup/reconnection, handoff-running, terminal debounce/kill/reopen, questions, attachments, voice and metrics suites plus case-chat utils and composer-scroll browser tests must remain green.
