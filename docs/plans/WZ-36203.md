# WZ-36203 — Opt-in conversation Wizz

## Expected outcome and classification

Add an accessible, default-off Wizz toggle which produces one short conversation-panel-only visual effect at the completion of an observed live agent response, never on history replay and without disturbing scroll or final layout.

Ticket: https://whoz.atlassian.net/browse/WZ-36203

Type: User Story; delivery classification: feature. This is not a bug; reproduction steps and a root-cause claim are not applicable. At analysis time the ticket has no comments, attachments, linked issues or remote links. The explicit Factory execution request supersedes the original description's backlog/no-Factory scheduling note for this execution only; do not edit other Jira fields.

**Reporter clarification, approved in this conversation:** prefer missing a decorative effect over animating history. Require ThinkingEvent or TextChunkEvent, then a new agent MessageEvent, then AgentFinishedEvent on the same connection. Replies without live-generation evidence, including some confirmation flows or reconnection windows, may have no effect. This is an explicit exception to exhaustive response coverage, not an undocumented timing heuristic.

## Acceptance criteria

From the ticket:

1. A Wizz button in the conversation toggles the effect, initially off, with clearly visible active state.
2. When enabled, a newly completed agent response briefly shakes only the conversation panel, not the page.
3. One effect per completed response; none per streaming chunk, user message, tool call, technical event or history load.
4. No effect-induced scrolling or change to final layout.
5. Reduced-motion preference replaces shaking with a short stationary highlight.
6. Accessible name, keyboard operation and exposed toggle state; follow existing visual/language conventions.
7. Frontend only, no sound, no dependencies, no persistence, no agent-engine/backend changes; reuse the existing completion signal.
8. Automated frontend coverage for toggling, completion, intermediate/history exclusion and reduced motion; visual scroll/layout validation.

Derived design decisions:

- Wizz defaults off again on case switch/reopen/component recreation. Enabling never replays a previous effect; disabling cancels an active effect.
- A qualifying turn contains a non-empty AGENT message after transient live evidence. Match its actor id to the finishing agent id; consume the candidate even when disabled.
- Deduplicate events before detection. Reset pending evidence on transport error/open/retry, turn replacement, user input events, terminal status and destruction. Ignore obsolete connection callbacks.
- AgentFinishedEvent alone owns triggering; neither isRunning changes nor IDLE status are a substitute.

### Read-only protocol evidence

All arrive on `case-event`; there is no history-complete marker. EventSource open is NOT a history/live boundary; first-seen ids alone do not exclude initial history. Do not use elapsed-time or browser/server-clock comparisons.

`agentos/agentos-service/src/main/kotlin/io/whozoss/agentos/agent/AgentAdvanced.kt` emits Thinking in the regular intention loop and TextChunk in final generation before the final agent message/completion. Pre-flight confirmation clarification/abort can finish without those transient signs. The approved conservative rule handles this by suppression. Because replay precedes queued transient evidence, requiring a NEW message after evidence excludes replayed completions. If that message was already replayed before buffered evidence arrives, suppress rather than recover it.

## Scoped implementation, file by file

### Frontend

1. **New `libs/agentos-ui/src/lib/components/case-chat/wizz-response-tracker.ts`**: a tiny component-owned pure tracker, no injectable singleton or event bus. Consume only current-case, first-seen events. Track live evidence and a qualifying non-empty agent-message actor id. Selected/Running replacement turns reset candidates; USER messages/AnswerEvent and terminal/error boundaries invalidate unfinished candidates. Thinking/TextChunk arm evidence but never trigger. AgentFinished consumes state unconditionally, yielding true only for a matching agent message after live evidence. Multiple messages/chunks in a turn still yield one effect. Normalise UUID casing for identity comparison; if ordering/identity is unsafe, suppress. Expose reset for connection/lifecycle boundaries. Do not clear the UI toggle on every turn.
2. **`case-chat.component.ts`**: add local default-off enabled signal, tracker and finite effect state. Feed tracker after existing dedup but before event-specific early returns. Check enabled only at qualifying completion. No new API requests, EventSources, preference/storage writes or dependencies. Reset pending evidence on error AND open (including automatic reconnect); open only resets, never declares subsequent durable events live. Capture case/source generation so stale handlers cannot affect another case. Cancel effects/timers on disable, retry/error/open, case switch and destroy; switch/reopen additionally turn the setting off. Use alternating CSS animation names or equivalent explicit render-boundary restart so a second eligible completion during an animation retriggers reliably. Clear effect state with a cancelable timer guarded against stale callbacks. No scroll/focus calls or timeline mutation in the Wizz path; preserve existing ingestion effects.
3. **`case-chat.component.html`**: native `button type="button"`, visible Wizz label, meaningful accessible name/title, bound aria-pressed, active and focus-visible styling. Native Enter/Space operation, available even while agent runs. Bind effect classes only on `.case-chat__messages-region`. Never rebuild/move the messages DOM to restart animation.
4. **`case-chat.component.scss`**: small horizontal transform-only shake (approximately 3px/350ms), beginning/ending at rest, no retained transform/fill state. Reduced-motion media query replaces it with geometry-neutral inset shadow/colour highlight, explicitly no movement. Use theme tokens; no dimensions, margins, padding, positional offsets or global selectors changed. Confirm transformed bounds do not create ancestor scrolling.
5. **New `wizz-response-tracker.spec.ts` in the same directory**: deterministic event ordering, identity/role checks, candidate consumption and reset tests.
6. **`case-chat.component.spec.ts`**: extend existing fake-stream tests for enabled gating, dedup, automatic reconnect/open/error, retry/navigation/teardown and deterministic animation restart/cancellation. Use fake timers as appropriate.
7. **New `apps/client-e2e/src/wizz.spec.ts`**: follow composer-scroll's isolated backend pattern; controlled SSE dispatch on the case stream, real native-button accessibility and browser animation/geometry checks. Keep mocks local; no shared harness refactoring required.

## Verification and risk

Risk: **medium**, despite small visual scope, because the host component is large/frequently changed and history/reconnect semantics are subtle.

Required tests:

- Off by default; click/Enter/Space toggle; accessible name, pressed and visible active states; no persistence/API writes; switch/reopen/recreation reset.
- Enabled Running → Thinking → many chunks → non-empty AGENT Message → matching Finished produces exactly one effect and none earlier. Thinking + final message also works without chunks.
- Multiple messages in a turn produce one effect; two eligible turns (including overlap) retrigger and return to rest.
- Disabled completion, user/system/empty messages, technical/tool events, tool-only turns, IDLE without completion, mismatched identity and duplicate completion never trigger.
- Slow initial replay with toggle enabled partway through never triggers. Unseen durable replay after retry/reconnect never qualifies. Seen frames stay deduplicated. Buffered transient signs after a replayed completion cannot leak into an unrelated turn.
- Responses without transient evidence and responses whose evidence was lost on disconnect are deliberately suppressed (reporter-approved).
- Case switch, terminal/error/transport boundary or destroy clears pending detection/effect. Obsolete sources/timers cannot animate a new case.
- Browser reduced-motion emulation verifies stationary highlight, no transform movement; normal motion affects only messages-region, not header/composer/sidebar/drawer.
- Long-history browser test away from bottom: compare scrollTop, scrollHeight/client dimensions and surrounding bounding boxes before/during/after Wizz. Compare Wizz off/on for identical message appends so ordinary new-content effects are not mistaken for effect-induced scroll. Check magnetic-bottom behaviour remains intact, narrow/mobile and short windows, open drawer, focus and text selection. Final geometry equals baseline.

Keep existing case-chat reconnect/dedup, handoff-running, kill/reopen replay/terminal debounce, question, submit/attachments/voice and turn-metrics tests green, plus `apps/client-e2e/src/composer-scroll.spec.ts`.
