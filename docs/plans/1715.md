# 1715 — Group tool calls and make the chat feel like Coday is actively working

Issue: https://github.com/whoz-oss/coday/issues/1715 (type: improvement, not a bug)
Base branch: `workstream/forge/master` · Work branch: `feature/1715-group-tool-calls`
Routes: **frontend** only

## 1. Expected outcome

In the AgentOS case chat, a run of consecutive tool calls shows as **one compact, collapsible group** instead of a
stack of separate cards. While a call in the group is still running, the group header says **in plain words what is
happening now** (e.g. `Reading README.md`) with a live pulse, so the user can see that Coday is working instead of
seeing a pile of ⏳ cards.

The issue has a title only (no description, comments, attachments or linked issues). The outcome above and all the
acceptance criteria below are derived from the title and from the current code.

## 2. Acceptance criteria (all derived — the issue has no description)

1. *(derived)* Two or more tool calls that follow each other in the timeline, with no message, question, delegation,
   notice or streaming bubble between them, are shown as a single **tool group**.
2. *(derived)* A single tool call alone stays shown as it is today: one tool card, no group.
3. *(derived)* Technical log rows (shown when the "technical logs" preference is on, e.g. `Tool selected`,
   `Intention → …`) do **not** split a group: when they sit between two tool calls they move into the group, in
   their original order. Rows before the first call or after the last call of a group stay outside.
4. *(derived)* A group is **collapsed by default**. Its header is a button with `aria-expanded`; clicking it shows
   the tool cards (and absorbed technical rows) exactly as they render today; each card keeps its own expand toggle.
5. *(derived)* While at least one call of the group has no response yet, the header shows a pulsing mark and the
   human sentence of the most recent pending call, from the existing `toolActivityLabel(toolName, args)`, plus the
   call count (e.g. `Reading README.md · 3 tools`). The header changes live as calls start and finish.
6. *(derived)* When every call of the group has answered, the header shows a static summary: `Ran N tools`,
   followed by `· K failed` when K > 0, with the error border/icon when K > 0 and the success one otherwise.
7. *(derived)* The expanded/collapsed state of a group survives new events arriving (the group keeps its identity
   while it grows) and is reset on a case switch, like the per-card state.
8. *(derived)* Nothing else changes: delegation cards, the "Show tool calls" toggle (off ⇒ no tool card and no
   group), turn metrics on agent messages, questions, notices, and the bottom activity line (`agentos-agent-activity`).

## 5. Scoped change (frontend)

### 5.1 New `libs/agentos-ui/src/lib/components/case-chat/tool-call-groups.ts`

A pure, framework-free function, so the rule is testable on its own:

```ts
export type ToolGroupEntry = Extract<TimelineItem, { kind: 'tool' } | { kind: 'technical' }>

/** Folds every run of 2+ tool items (technical rows between them absorbed) into one 'tool-group' item. */
export function groupConsecutiveToolCalls(items: TimelineItem[]): TimelineItem[]
```

Rule: walk the items; a run starts at a `tool` item and extends over following `tool` and `technical` items; it is
cut at the last `tool` item of that stretch (trailing technical rows are given back to the timeline). A run with
2+ tool items becomes `{ kind: 'tool-group', id: <requestId of its first call>, entries }`; a run with 1 tool item
is left untouched. Every other kind passes through unchanged and in order. To avoid an import cycle, define the
`TimelineItem`/`ToolCall` types where they are today and import them as types only (`import type`), or move these
types into this file and re-export them from the component — implementer's choice, the public names must not change.

Also export a small summary helper used by the template:

```ts
export interface ToolGroupSummary {
  running: boolean      // some call has no response
  label: string         // running: toolActivityLabel of the latest pending call; done: 'Ran N tools'
  count: number         // number of tool calls
  failed: number        // calls whose response.success === false
  detail?: string       // qualified tool name of the pending call (tooltip)
}
export function summarizeToolGroup(entries: ToolGroupEntry[]): ToolGroupSummary
```

### 5.2 `case-chat.component.ts`

- `TimelineItem`: add `| { kind: 'tool-group'; id: string; entries: ToolGroupEntry[] }`.
- `baseTimeline`: after the existing `isLastInGroup` loop, `return groupConsecutiveToolCalls(items)`. Do it last so
  metrics/indices computed on `items` are unaffected (message objects are the same references).
- `trackTimelineItem`: `case 'tool-group': return \`tool-group-${item.id}\``.
- New state: `expandedToolGroups = signal<Set<string>>(new Set())`, `toggleToolGroup(id)`,
  `isToolGroupExpanded(id)` (same shape as `collapsedTools`/`toggleToolCall`); clear it in `reinitialise()`.
- `protected toolGroupSummary(item)` delegating to `summarizeToolGroup`. Import `NgTemplateOutlet`.

### 5.3 `case-chat.component.html`

- Move the current tool card markup (the final `@else` branch) and the technical row markup into two
  `<ng-template>`s (`#toolCallCard let-call`, `#technicalRow let-item`) and render them with `ngTemplateOutlet` in
  their existing branches — no change to their markup, classes or behaviour.
- Add an `@else if (item.kind === 'tool-group')` branch:
  - container `div.case-chat__tool-group` with modifiers `--running`, `--success`, `--error`;
  - header `button.case-chat__tool-group-header` (`type="button"`, `[attr.aria-expanded]`, `[title]` = summary
    detail) containing: pulse `span.case-chat__tool-group-pulse` when running (else ✅/❌ icon like the cards),
    `span.case-chat__tool-group-label` (summary label), `span.case-chat__tool-group-count` (`· N tools` when running,
    `· K failed` when done and K > 0), chevron;
  - when expanded, `div.case-chat__tool-group-body` iterating `entries` and rendering each with the two templates.

### 5.4 `case-chat.component.scss`

`&__tool-group*` styles in the tool-call family: same border/radius/font size as `&__tool-call`, border colour by
state; body with a left rule and a small gap so nested cards read as children; a pulse square + keyframes aligned
with `agent-activity.component.scss`, disabled under `prefers-reduced-motion: reduce`; label with ellipsis on one line.

## 6. Verification

New `libs/agentos-ui/src/lib/components/case-chat/tool-call-groups.spec.ts`:
- 2 adjacent tool items → one group, entries in order, `id` = first requestId; 1 tool item → unchanged.
- message / question / delegation / notice / streaming between tools → two separate runs (no group or two groups).
- technical rows between tools absorbed; technical rows before the first / after the last tool stay outside.
- `summarizeToolGroup`: running label = `toolActivityLabel` of the latest pending call (e.g.
  `FILES__readFile` + `{"filePath":"README.md"}` → `Reading README.md`), count; done → `Ran 3 tools`, `failed`
  counted from `response.success === false`.

`case-chat.component.spec.ts` (instance-level, no rendering, like the existing timeline tests):
- `ToolRequest/Response` events for two calls → `timeline()` has one `tool-group` with both calls; a single call →
  one `tool` item.
- `showToolCallsOverride` false → no `tool` nor `tool-group` items.
- the delegate test (`replaces the generic delegate tool card…`) still yields exactly one `delegation` item.
- `toggleToolGroup` / `isToolGroupExpanded` toggle, and `reinitialise()` clears them.
- group id stable when a third call is appended to the events.

Must stay green: `pnpm nx run-many -t lint test -p agentos-ui` (all existing case-chat, agent-activity, delegation
specs), and `pnpm nx run-many -t build`.

Manual check (`pnpm web:serve:dev`): a turn with several file reads shows one group whose header changes from
`Reading a.ts · 2 tools` to `Ran 3 tools`; expand/collapse; a failing tool turns the group red with `· 1 failed`;
technical logs on/off; Show tool calls off; delegation cards unchanged; mobile width (header ellipsis).

**Risk: low.** Frontend presentation only, one component, no API or data change; the main risk is a timeline
ordering regression, covered by the pure-function tests and the existing timeline specs.
