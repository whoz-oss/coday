# WZ-36388: Restrict the Factory Admin menu to AgentOS administrators

Jira: https://whoz.atlassian.net/browse/WZ-36388 (User Story, epic WZ-36044)
Depends on: [WZ-36378](https://whoz.atlassian.net/browse/WZ-36378). It adds the Admin page and the run-concurrency
endpoints (plan `docs/plans/WZ-36378.md`).
Branch: `work/forge/WZ-36388-admin-role-check`, stacked on `work/forge/WZ-36378-parallel-workflow-runs`.
Rebase it onto `workstream/forge/master` once WZ-36378 is merged.
Sides: **backend + frontend** (backend first).

## 1. Expected outcome

Only AgentOS administrators (the `isAdmin` flag of the AgentOS user) can see the Factory cockpit **Admin** menu and
call the run-concurrency settings endpoints. Every other user gets a 403 `FORBIDDEN_ADMIN_REQUIRED` from Factory, and
the menu is hidden for them. The check is owned by **factory-service** and is applied **only to the Admin menu** for
now.

## 2. Acceptance criteria

From the ticket:

- **AC1**: in `auth` mode, an AgentOS non-admin gets **403 `FORBIDDEN_ADMIN_REQUIRED`** on `GET` and `PUT
  /api/factory/admin/settings/run-concurrency`, and the stored value is unchanged.
- **AC2**: an AgentOS admin reads and updates the setting exactly as described in WZ-36378.
- **AC3**: when AgentOS cannot be reached or answers badly, the caller is **not** admin (fail closed, 403).
- **AC4**: in `local` security mode, the single user is admin (local installs keep working unchanged).
- **AC5**: the cockpit hides the Admin nav entry for non-admins, and `/admin` redirects them to `/workstreams`.
- **AC6**: no other Factory endpoint changes behaviour. This includes `/api/factory/admin/artifacts/*`.

Criteria I derived (flagged **[derived]**):

- **AC7 [derived]**: the admin answer is cached for 60 s per user, so the cockpit does not call AgentOS on every request.
  Transport errors are **not** cached, so a recovering AgentOS is seen at once. A revoked admin loses access within
  60 s at most.
- **AC8 [derived]**: `GET /api/factory/me` returns `{ data: { userId, isAdmin } }`. It is the single source the cockpit
  uses to decide what to show.

## 3. Why factory-service, and why AgentOS is the authority

- Today Factory has **no role model**.
  - `AuthenticatedUser` (`web/AuthenticatedUser.kt`) only holds `userId` and `organizationId`.
  - `MembershipResolver` only resolves the organization.
  - `ForbiddenAdminRequiredException` (`error/FactoryException.kt`, 403 `FORBIDDEN_ADMIN_REQUIRED`) is declared but
    never thrown.
- AgentOS already owns the authority: `Caller.isAdmin`, the Super Admin flag of the user record, exposed by `GET
  /api/users/me` under the caller's `X-External-User-Id`. The Coday setup wizard already relies on it
  (`apps/server/src/lib/setup/agentos-client.ts#getMe`).
- A second admin registry inside Factory would drift. So Factory **asks** AgentOS, through the HTTP boundary it already
  uses (`AgentOsProxyClient` / `HttpAgentOsProxyClient`), and makes the decision server-side. The cockpit only mirrors
  that decision for UX.
- **Why not `AuthenticationFilter`**: adding `isAdmin` there would make **every** `/api` request call AgentOS. That
  costs latency and couples every endpoint to AgentOS availability, while only the Admin menu needs the check (AC6).
  The check therefore stays an explicit, opt-in service call inside the admin controller(s).

## 4. Scoped change

### 4.1 Backend (`factory/factory-service`, implement first)

**a) AgentOS relay**: `proxy/AgentOsProxyClient.kt`, `proxy/HttpAgentOsProxyClient.kt`

- Add `data class AgentOsCurrentUser(val externalId: String?, val isAdmin: Boolean)` next to `RunCostDto`.
- Add `fun fetchCurrentUser(externalUserId: String): AgentOsCurrentUser? = null` to the interface. It is defaulted so
  existing doubles and mocks stay source-compatible, like `fetchNamespaceGit`.
- Implement it in `HttpAgentOsProxyClient`:
  - It uses `relay("/api/users/me", externalUserId, Map<String, Any?>)` and maps `isAdmin` **only if it is a JSON
    boolean `true`**. Anything else is `false`.
  - A 404 returns null.
  - Other failures throw `AgentOsUnavailableException`, as the other relays do.

**b) Authorization service**: new `web/security/AdminAuthorizationService.kt` (`@Service`)

- Constructor: `FactoryProperties` (for `security.mode`), `AgentOsProxyClient`, `Clock` (default `Clock.systemUTC()`),
  and `ttl: Duration = 60s`.
- `fun isAdmin(user: AuthenticatedUser): Boolean`
  - In `SecurityMode.LOCAL` it returns `true` without calling AgentOS (AC4).
  - In `SecurityMode.AUTH` it reads the cache entry for `user.userId`; on a miss or an expired entry it calls
    `fetchCurrentUser(user.userId)`.
  - A non-null answer is cached (true **or** false) and its flag is returned.
  - A null answer or any exception returns `false`, logs a WARN without the stack trace, and is **not cached**
    (AC3, AC7).
- `fun requireAdmin(user: AuthenticatedUser)`: if `!isAdmin(user)`, it throws `ForbiddenAdminRequiredException()`. The
  existing `FactoryExceptionHandler` renders it as `{ error: { code: "FORBIDDEN_ADMIN_REQUIRED", ... } }`.
- Cache: a `ConcurrentHashMap<String, Pair<Boolean, Instant>>`, bounded by the number of distinct admin-page users. No
  new dependency.
- Identity forwarded to AgentOS: `user.userId`, which is the same `X-External-User-Id` value the rest of Factory relays
  (see `WorkflowRunCostReaderHttpTest`).

**c) Apply the check to the Admin menu only**: `settings/web/RunConcurrencyAdminController.kt` (created by WZ-36378)

- Inject `AdminAuthorizationService` and call `requireAdmin(user)` as the first statement of `GET` and `PUT`. The
  service and the persistence code are untouched.
- `ArtifactAdminController` and every other controller are **not** modified (AC6).

**d) Current-user endpoint**: new `web/CurrentUserController.kt`

- `GET /api/factory/me` returns `mapOf("data" to mapOf("userId" to user.userId, "isAdmin" to admin.isAdmin(user)))`.
- It is authenticated by the existing `AuthenticationFilter`. It is not added to `PUBLIC_API_PATHS`.

**e) OpenAPI**: in `factory/factory-service/openapi/factory-openapi.yaml`, add `GET /api/factory/me` and the 403
`FORBIDDEN_ADMIN_REQUIRED` response on the two run-concurrency operations. Use the same procedure as in WZ-36378
(regenerate, or edit by hand in the same style). The narrow HTTP_API contracts are not touched.

### 4.2 Frontend (`apps/factory-cockpit`, after the backend). UX only; the backend stays the authority.

- `core/factory-api.service.ts`: add `export interface CurrentUser { userId: string; isAdmin: boolean }` and
  `getCurrentUser(): Observable<CurrentUser>`, which reuses `request` on `/api/factory/me`.
- New `core/current-user-state.service.ts`: `@Injectable({ providedIn: 'root' })`.
  - It exposes the signals `isAdmin = signal(false)` and `loaded = signal(false)`.
  - `ensureLoaded(): Observable<boolean>` loads once and shares the request. On error it sets `isAdmin` to false and
    `loaded` to true.
- `layout/shell.component.ts`: call `ensureLoaded()` in the constructor, and make `nav` a `computed`. The base entries
  are always present; `{ label: 'Admin', icon: 'tune', link: '/admin' }` is appended only when `isAdmin()` is true.
  `shell.component.html` is unchanged, since it already iterates `nav` (now `nav()`).
- New `core/admin.guard.ts`: functional `CanActivateFn` returning `ensureLoaded().pipe(map(isAdmin => isAdmin ||
  router.createUrlTree(['/workstreams'])))`.
- `app.routes.ts`: add `canActivate: [adminGuard]` on the `admin` route.
- `features/admin/admin-page.component.*`: when a load or save error has `status === 403` and code
  `FORBIDDEN_ADMIN_REQUIRED`, show an "Administrator access required" state with no form. This covers a role revoked
  while the page is open.

### 4.3 Contract

```
GET /api/factory/me
200 { "data": { "userId": "alice@example.com", "isAdmin": true } }

GET|PUT /api/factory/admin/settings/run-concurrency   (contract of WZ-36378, plus:)
403 { "error": { "code": "FORBIDDEN_ADMIN_REQUIRED", "message": "Admin authorization required", "details": null } }

Factory -> AgentOS (server side, never from the browser)
GET /api/users/me   header X-External-User-Id: <user.userId>   -> { ..., "isAdmin": true|false }
```

### 4.4 Implementation order

1. Relay `fetchCurrentUser`.
2. `AdminAuthorizationService` and its unit tests.
3. `requireAdmin` in `RunConcurrencyAdminController`, plus `CurrentUserController` and its HTTP tests.
4. OpenAPI.
5. Cockpit: API, state service, shell, guard, admin page 403 state, and their specs.

### 4.5 Out of scope (separate ticket proposed)

- Applying `requireAdmin` to `/api/factory/admin/artifacts/*` and to any other governance endpoint.
- A role model richer than AgentOS Super Admin (per-organization or per-namespace Factory admins).

## 5. Verification

### 5.1 Tests to add

Backend:

- `web/security/AdminAuthorizationServiceTest.kt` (MockK, fixed `Clock`):
  - `local` mode returns true and never calls the proxy.
  - `auth` mode returns true or false depending on AgentOS `isAdmin`.
  - When the proxy throws, it returns false, and the next call calls the proxy again (not cached).
  - When the proxy returns null, it returns false.
  - Two calls within 60 s make one proxy call; after 60 s, a new call is made.
  - `requireAdmin` throws `ForbiddenAdminRequiredException` for a non-admin.
- `proxy/HttpAgentOsProxyClient` mapping: `isAdmin: true` gives true. `false`, missing, or `"true"` as a string give
  false.
- `settings/RunConcurrencyAdminAuthHttpTest.kt`: `@TestPropertySource(factory.security.mode=auth)` plus a `@Primary`
  `AgentOsProxyClient` mockk, same pattern as `WorkflowRunCostReaderHttpTest`.
  - A non-admin gets 403 `FORBIDDEN_ADMIN_REQUIRED` on GET and on PUT. A GET as admin afterwards still shows the old
    value.
  - An admin gets 200 on GET and PUT.
  - When AgentOS throws, the caller gets 403.
  - `GET /api/factory/me` returns `{userId, isAdmin}` for both an admin and a non-admin.
- The existing `RunConcurrencyAdminControllerHttpTest` from WZ-36378 runs in `local` mode and must stay green, since the
  local user is admin.

Frontend (Jest):

- `core/current-user-state.service.spec.ts`: loads once; on error, `isAdmin` is false.
- `core/admin.guard.spec.ts`: an admin returns true; a non-admin returns a UrlTree to `/workstreams`.
- `layout/shell.component.spec.ts`:
  - With an admin, the `a[href="/admin"]` link exists; with a non-admin, it does not.
  - The existing assertions stay green: `/workflows` present, no `/reglages`, no "Settings" text.
- `features/admin/admin-page.component.spec.ts`: a 403 `FORBIDDEN_ADMIN_REQUIRED` shows the access-required state and
  no form.

### 5.2 Must stay green

`./gradlew test` in `factory/` (especially `ArtifactAdmin*` tests: unchanged behaviour) and
`pnpm nx run-many -t lint test -p factory-cockpit`.

### 5.3 Manual checks

- With `--auth` and two users (one AgentOS Super Admin, one not), check that the menu is visible only for the admin
  and that calling the endpoint directly as the non-admin gives a 403.
- With AgentOS stopped while Factory runs, the Admin page shows the access-required state and other pages keep working.
- A local install (`local` mode) still shows the Admin menu.

## 6. Risk level

**Low to medium.** The change adds one cross-service call, limited to admin paths, and it fails closed. Other
endpoints are untouched. The main risk is the identity forwarded to AgentOS not matching the AgentOS user, which would
lock admins out (never the reverse). The auth-mode HTTP test and the manual two-user check cover it.
