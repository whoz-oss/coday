# WZ-36378 — Configurable parallel workflow runs (default 5)

Jira: https://whoz.atlassian.net/browse/WZ-36378 (User Story, epic WZ-36044 "FP - Forge - Feb 2027")
Branch: `work/forge/WZ-36378-parallel-workflow-runs` → PR base `workstream/forge/master`
Sides: **backend + frontend** (backend first)

## 1. Expected outcome

The Factory outbox drain stops running one workflow continuation at a time: up to *N* continuations
(default **5**) run concurrently on a bounded worker pool, extra ones stay queued and are dispatched
when a slot frees, and an administrator can read and change *N* (integer ≥ 1) from a new **Admin**
page of the Factory cockpit, without restarting Factory.

## 2. Acceptance criteria

From the ticket:

- **AC1**: by default, up to 5 workflow runs execute concurrently without blocking each other in the
  outbox drain worker.
- **AC2**: when more than N runs are active, the extra runs stay queued (`pending` continuation) and are
  picked up automatically once a slot frees.
- **AC3**: an administrator can set the maximum number of parallel runs in the Factory Admin interface.
  The default is 5 and values below 1 are rejected.
- **AC4**: per-workflow locking and worktree occupancy checks still stop two steps of the same run from
  colliding on the same worktree.

Criteria I derived (flagged **[derived]**):

- **AC5 [derived]**: the value is persisted and survives a Factory restart. It applies at runtime, with no
  restart. Lowering it never interrupts runs already in flight: it only stops new dispatches until the
  in-flight count drops below the new limit.
- **AC6 [derived]**: there is a hard upper bound (**20**) so a typo cannot create an unbounded thread
  pool. Values above it are rejected with 400.
- **AC7 [derived]**: setting the value to 1 gives back exactly the old serialized behaviour. This is the
  operational escape hatch.
- **AC8 [derived]**: when a run lasts longer than the 2 h continuation lease, the next tick does not
  claim that continuation again while it is still executing in this process. Real concurrency makes this
  failure possible; the old blocked thread made it impossible.
- **AC9 [derived]**: on graceful shutdown, in-flight continuations are interrupted and their claim is
  released. This keeps the current interruption contract.

## 4. Analysis

### 4.1 Root cause of the 1-run serialization (confirmed)

`factory/factory-service/src/main/kotlin/io/whozoss/factory/agentattempt/service/OutboxDrainWorker.kt`:

- `drain()` is `@Scheduled(fixedDelay = factory.outbox.drain-interval-ms:5000)` and `@Synchronized`. It
  runs on the single Spring scheduler thread enabled by `config/OutboxSchedulingConfiguration.kt`.
- The second loop (`for (candidate in due)`) claims each continuation and calls
  `sessionRunService.runSession(...)` **synchronously**.
- `SessionRunService.runSession` → `runSessionLocked` → `executeStep` →
  `CapabilityExecutionService.resolveAndRecord` → `resolveAgentViaAdapter` → `executeRemoteTurn` →
  `AgentOsSseClient.observe(...)` blocks for the whole AgentOS turn (minutes to hours). It can also run a
  local verification process (`resolveCode`).
- Result: while one continuation runs, the tick thread is blocked and every other `pending` continuation
  waits. `BridgeRecoveryWorker.sweepTerminalOccupancies` (also `@Scheduled` on the same default
  single-thread scheduler) is starved as well.

### 4.2 Existing safety nets that stay in place (AC4)

- **One continuation node per workflow**: `OutboxDrainService.continuationId(workstreamId, namespaceId,
  workflowId)` is deterministic. `claimContinuation` is a CAS on `status`/`leaseUntil`
  (`SpringDataNeo4jOutboxRepository.claimContinuation`). A workflow therefore never has two claimed
  continuations. A wake that arrives while it is claimed sets `wakeRequested` and re-pends it on
  acknowledge.
- `SessionRunService.runLocks` (static `ConcurrentHashMap<String, ReentrantLock>` keyed per
  org|ws|ns|workflow) serializes runs of the same workflow inside the process.
- `RunService.runWriteLocks` (static) serializes parent-Run transitions.
- `CapabilityExecutionService.reservationLocks` (static) serializes attempt register+claim.
- `WorktreeExecutionOccupancyService` / `Neo4jWorktreeExecutionOccupancyRepository` fence physical
  worktrees in Neo4j and retry on deadlock. Agent and code steps that find the worktree occupied defer
  (`AGENT_WORKTREE_OCCUPIED`) or refuse (`WORKTREE_OCCUPIED`) with no side effect.

All of these are process-wide (static or Neo4j) and thread-safe, so they keep working on several
threads. No change is needed in them.

### 4.3 Admin surface today

- Backend: the only admin controller is
  `factory/factory-service/src/main/kotlin/io/whozoss/factory/artifact/web/ArtifactAdminController.kt`
  (`/api/factory/admin/artifacts/*`). It accepts any authenticated user (`AuthenticatedUser`) and wraps
  responses as `{ data }`. Errors go through `FactoryException` → `FactoryExceptionHandler`.
- No settings persistence exists. Neo4j constraints are created in `config/Neo4jSchemaInitializer.kt`.
- Frontend (`apps/factory-cockpit`): there is no admin page. `features/admin/` only holds
  `confirm-dialog.component.ts` and an empty `admin-page.component.scss`. The nav is defined in
  `layout/shell.component.ts` (Workstreams / History / Workflows). `layout/shell.component.spec.ts`
  asserts that the shell text **does not contain "Settings"** and has no `/reglages` link, so the new
  entry must be labelled **"Admin"** and routed at `/admin`, and the `reglages → workflows` redirect
  must stay.
- HTTP pattern: `core/factory-api.service.ts` (pure HTTP, unwraps `{data}`, normalizes errors). It has
  no `put` helper yet. Page-scoped state service pattern: `core/workflow-definitions-state.service.ts`
  (signals + `@Injectable()` provided by the page).
- The Express proxy (`apps/server/src/lib/factory-proxy.ts`) forwards every method under
  `/api/factory/*` as-is. No change is needed there.

### 4.4 Regression risk areas

- Concurrent Neo4j transactions from several workflows (embedded engine). Writes target distinct nodes
  per workflow. The only shared hot node is the occupancy node, which already retries on deadlock.
- Long runs that outlive `OutboxDrainService.LEASE_SECONDS` (2 h): see AC8. This needs an in-process
  in-flight guard.
- The worker shutdown and interruption path (`releaseContinuation`), covered by an existing test.
- `OutboxDrainWorkerTest` assumes `drain()` is synchronous. It needs a synchronous executor seam.
- Spring Boot auto-configures an `applicationTaskExecutor` bean of type `Executor`. The worker **must
  not** declare a constructor parameter of type `Executor`/`ExecutorService`, or Spring will inject that
  shared pool. Use a dedicated functional type (see below).

## 5. Scoped change

### 5.1 Backend (implement first)

**a) Setting model + persistence: new package `io.whozoss.factory.settings`**

- `settings/RunConcurrencySettingsService.kt` (`@Service`):
  - Constants: `MIN = 1`, `MAX = 20` (hard ceiling), the property key.
  - Constructor: `Neo4jClient`, `@Value("\${factory.outbox.max-parallel-runs:5}") defaultMaxParallelRuns: Int`
    (clamped into [1, 20] at boot, with a WARN if it was out of range).
  - Keeps the current value in an `AtomicInteger`, loaded lazily on first read (or eagerly with
    `@PostConstruct`, fail-soft: on DB error, log a WARN and use the default).
  - `fun maxParallelRuns(): Int`: hot path, memory only, never touches Neo4j after the first load.
  - `fun settings(): RunConcurrencySettings`: returns the value plus the metadata below.
  - `fun update(value: Int, actorId: String): RunConcurrencySettings`: validates `value in MIN..MAX`.
    Otherwise it throws
    `BadRequestException`-style `FactoryException(400, "INVALID_MAX_PARALLEL_RUNS", ..., details = mapOf("min" to 1, "max" to 20))`.
    Add a small `InvalidRunConcurrencyException : FactoryException` in the same package. It then MERGEs
    the node and updates the `AtomicInteger` **after** the write succeeds.
  - Persistence: a single global node
    `(:FactorySetting {id: 'outbox.max-parallel-runs', intValue, updatedAt, updatedBy})` written with
    `Neo4jClient` MERGE (same style as `Neo4jWorktreeExecutionOccupancyRepository`). Scope: **per Factory
    instance** (global), because the drain pool is process-wide and serves every organization. Document
    this in the KDoc.
  - `data class RunConcurrencySettings(val maxParallelRuns: Int, val defaultMaxParallelRuns: Int, val min: Int, val max: Int, val updatedAt: Instant?, val updatedBy: String?)`.
- `config/Neo4jSchemaInitializer.kt`: add
  `CREATE CONSTRAINT factory_setting_id_unique IF NOT EXISTS FOR (s:FactorySetting) REQUIRE s.id IS UNIQUE`.
- `src/main/resources/application.yml`, under `factory.outbox`: add
  `max-parallel-runs: ${FACTORY_OUTBOX_MAX_PARALLEL_RUNS:5}` with a comment ("default used until an
  admin persists a value; hard ceiling 20").

**b) Admin API: `settings/web/RunConcurrencyAdminController.kt`**

- `@RestController @RequestMapping("/api/factory/admin/settings/run-concurrency")`. Authorization is the
  same as `ArtifactAdminController`: an `AuthenticatedUser` parameter, any authenticated user.
- `GET` → `mapOf("data" to service.settings())`.
- `PUT` (consumes JSON) body `Map<String, Any?>?`: `maxParallelRuns` must be a JSON **integer**
  (`Int`, or `Long` within range). A missing value, a non-integer (e.g. `2.5`, `"5"`, boolean) or a value
  out of [1, 20] gives **400** `INVALID_MAX_PARALLEL_RUNS`. Success returns `{data: settings}` with
  `updatedBy = user.userId`.
- Log an INFO audit line on change (old → new, actor).

**c) Concurrent dispatch: `agentattempt/service/OutboxDrainWorker.kt`**

- New constructor parameters, appended **after** `clock` with defaults so that Spring wiring and the
  existing tests keep compiling:
  - `private val concurrency: RunConcurrencyLimit = RunConcurrencyLimit { 5 }`, where
    `fun interface RunConcurrencyLimit { fun current(): Int }` is declared in the settings package and
    implemented by `RunConcurrencySettingsService` (`override fun current() = maxParallelRuns()`). Spring
    injects the service bean; tests pass a lambda.
  - `private val continuationExecutor: ContinuationExecutor? = null`, where
    `fun interface ContinuationExecutor { fun execute(task: Runnable) }` is a dedicated type (**not**
    `java.util.concurrent.Executor`, see §4.4). When it is null, the worker owns
    `ThreadPoolExecutor(0, RunConcurrencySettingsService.MAX, 60s, SynchronousQueue, daemon named threads "factory-run-worker-%d")`.
- State: `private val inFlight = ConcurrentHashMap.newKeySet<String>()` with keys
  `"$organizationId|${event.id}"`.
- `drain()` keeps `@Scheduled` + `@Synchronized` (tick-level exclusion) and the first loop
  (`drainPending` handoff) **unchanged**. Second loop:
  1. `if (inFlight.size >= concurrency.current().coerceIn(1, MAX)) return`. Check this **before every
     claim** so that the remaining due continuations stay `pending`/unclaimed (AC2). Read the limit fresh
     on each check (AC5).
  2. Skip a candidate whose key is already in `inFlight` (AC8).
  3. `claimContinuation` stays on the tick thread (short CAS). If it returns null, `continue`.
  4. Add the key to `inFlight`, then submit `executeContinuation(organizationId, event, token)` to the
     executor. On `RejectedExecutionException` (or any submit failure): remove the key, call
     `drainService.releaseContinuation(organizationId, event.id, token)` and stop the loop for this tick.
- `private fun executeContinuation(organizationId, event, token)`: move the current `try { … } catch`
  body here **verbatim** (parse → `runSession` → `completeContinuation`; interruption → fenced release
  and re-interrupt; other errors → `deferContinuation`), wrapped in `try { … } finally { inFlight.remove(key) }`.
  The interruption branch no longer `return`s from the tick. It ends the task only, which is the correct
  per-thread semantics.
- Freed slots are filled at the next tick (≤ `drain-interval-ms`, 5 s by default). That is enough for
  AC2; no immediate re-dispatch callback is needed (KISS).
- `@PreDestroy fun shutdown()`: if the pool is owned by the worker, `shutdownNow()` then
  `awaitTermination(10s)`. The interrupted tasks release their claim through the existing interruption
  branch (AC9). A claim that is not released falls back to lease recovery, as today.
- Update the class KDoc: remove the "does not introduce an executor" sentence and describe the bounded
  pool, the per-tick limit check, the in-flight guard and the fact that per-workflow serialization comes
  from the deterministic continuation id + CAS + `runLocks`. Also update the comment on
  `OutboxDrainService.LEASE_SECONDS` ("Full sequencer turns still run on the existing scheduler…") to
  say they run on the bounded run pool. Comments only, no logic change in `OutboxDrainService`.
- Optional, small: `fun activeRuns(): Int = inFlight.size` (used for logging only). **Do not** expose it
  in the API (out of scope).

**d) OpenAPI**: add the two operations to `factory/factory-service/openapi/factory-openapi.yaml`. Use
`./gradlew :factory-service:generateOpenApiDocs` if it runs in the environment; otherwise hand-add the
two path entries in the same style as `/api/factory/admin/artifacts/gc`. The narrow HTTP_API contracts
(worker/workstream/authoring) are **not** touched.

### 5.3 Contract between frontend and backend

```
GET  /api/factory/admin/settings/run-concurrency
200  { "data": { "maxParallelRuns": 5, "defaultMaxParallelRuns": 5, "min": 1, "max": 20,
                 "updatedAt": null | "2026-…Z", "updatedBy": null | "user-id" } }

PUT  /api/factory/admin/settings/run-concurrency
     Content-Type: application/json
     { "maxParallelRuns": 7 }
200  { "data": { "maxParallelRuns": 7, "defaultMaxParallelRuns": 5, "min": 1, "max": 20,
                 "updatedAt": "2026-…Z", "updatedBy": "<caller userId>" } }
400  { "error": { "code": "INVALID_MAX_PARALLEL_RUNS",
                  "message": "maxParallelRuns must be an integer between 1 and 20",
                  "details": { "min": 1, "max": 20 } } }
401  standard UNAUTHENTICATED envelope (auth mode, no identity)
```

`updatedAt` is ISO-8601 (Jackson JSR-310 is already configured). The value takes effect at the next drain
tick, with no restart.

### 5.5 Out of scope (separate tickets proposed)

- A heartbeat or renewal of the continuation lease for runs longer than 2 h. Today a run that outlives
  the lease cannot acknowledge its continuation (token or lease fence), and the continuation is replayed
  after it finishes. The AC8 guard prevents the *concurrent* double-run, not this pre-existing replay.
- Exposing the live active-run count and queue depth in the Admin page or the cockpit pill.
- Per-organization or per-workstream quotas, and a role-based admin authorization model (today any
  authenticated user can call `/api/factory/admin/*`, consistent with the artifact admin commands).

## 6. Verification criteria

### 6.1 Tests to add

Backend (`factory/factory-service/src/test/kotlin/...`):

- `agentattempt/OutboxDrainWorkerTest.kt` (pure unit, MockK):
  - **Fails before, passes after**: `drain dispatches up to the limit concurrently and returns without
    waiting`. Seven due continuations of distinct workflows; `runSession` blocks on a latch; real
    worker-owned pool; limit 5. Assert that `drain()` returns within a short timeout, that exactly 5
    `runSession` calls are in progress at the same time (a `CountDownLatch(5)` is reached), and that
    `claimContinuation` was called exactly 5 times (2 are left unclaimed). Before the change, `drain()`

## 7. Risk level

**Medium.** The frontend part is low risk. The backend part turns a de-facto single-threaded runtime into
a concurrent one. Per-workflow and per-worktree exclusivity already relies on durable CAS claims and on
process-wide locks, which the change does not touch. The new risks (lease outliving, executor wiring,
shutdown) are each covered by an explicit guard and a test. Setting the value to 1 restores the old
behaviour.
