# WZ-36379 — Stopping a workflow run does not stop AgentOS agents and leaves the run RUNNING

- Jira: https://whoz.atlassian.net/browse/WZ-36379 (Bug)
- Branch: `work/forge/WZ-36379-stop-run-kills-agents` → base `workstream/forge/master`
- Sides concerned: **backend only** (factory-service). The Factory Cockpit already renders `cancelled`; no frontend change.
- Risk level: **medium** (concurrency between the cancel command and the sequencer thread; durable state machine).

## 1. Expected outcome

Clicking **Stop** on a running Factory run kills the AgentOS case and all its active descendant sub-cases with an authenticated
request, and the step and the run leave `running` for a terminal `cancelled` state (backend projection and cockpit), releasing the
worktree occupancy of the cancelled attempt.

**Observed vs expected.** Observed: `POST /api/factory/workflows/{workflowId}/attempts/{attemptId}/cancel` moves the durable attempt to
`interrupted / USER_CANCELLED`, but the AgentOS case keeps running and the step + run stay `running` forever (runs
`45717d0c-ede8-3ea9-b8e1-cf01447dc6bf`, `ddcb8f34-35af-317f-bc8d-8c8b0060a0d7`); the cockpit hides Stop because the attempt is terminal.
Expected: agents stopped, step `cancelled`, run `cancelled`, occupancy released. Reproduction steps: **complete** (start any agent
workflow, click Stop while the agent step runs).

## 2. Acceptance criteria

1. (ticket) Stop sends an authenticated kill to AgentOS (`POST /api/cases/{caseId}/kill` with `X-External-User-Id`), which stops the
   case and its active descendants (AgentOS `CaseServiceImpl.killCase` already kills `findActiveDescendants`).
2. (ticket) The stopped step and the run transition out of `running` to a terminal state, in the backend projection and in the
   cockpit.
3. (ticket) The worktree occupancy held by the cancelled attempt is released and the execution slot (the per-workflow sequencer
   lock / outbox continuation) is freed.
4. (derived) A kill HTTP failure is logged at WARN with the case id and status, never silently swallowed; cancellation of the
   durable attempt still proceeds (kill stays best-effort, never throws).
5. (derived) The terminal state is `cancelled` for the step and for the run; dependents become `blocked`; no new step is dispatched
   after a user cancellation, including by a later continuation.
6. (derived) Runs already stuck (attempt `interrupted/USER_CANCELLED`, step `running`) are healed by the next `runSession` of that
   workflow (e.g. `POST /continue`), without dispatching a new agent turn.
7. (derived) Occupancy is released only when AgentOS acknowledged the kill (2xx); otherwise it stays retained (fail-closed, existing
   policy).

## 4. Root cause (proof)

Three combined defects, one causal chain:

1. **Unauthenticated kill, silently swallowed** —
   `factory/factory-service/src/main/kotlin/io/whozoss/factory/adapter/agentos/DefaultAgentOsExecutionAdapter.kt`, `postKill(caseId)`:
   `client.post().uri("/api/cases/$caseId/kill").retrieve().toBodilessEntity()` sends no `X-External-User-Id` (every other call of
   the adapter does) and `catch (_: Exception) { // ignored }`. AgentOS rejects it (401/403) → the case and sub-cases keep running.
2. **Fencing exception leaves the step RUNNING** — `BridgeCancellationService.requestCancel` → `Neo4jDurableAgentAttemptRepository.cancel`
   rotates `ownerToken` to `cancel:$attemptId`. The sequencer thread later calls `finalizeAgentAttempt` →
   `DurableAgentAttemptService.finalize(... reservation.ownerToken ...)` → `assertNotFenced` throws `AttemptLeaseFencingException`.
   `SessionRunService.executeStep` catches it and `return null` ("leaving the step running for authoritative reconciliation"), but no
   authority exists for a user cancellation: the loop reloads the durable `running` step, finds nothing ready, exits, and
   `SessionSequencer.terminalStatus` (any `RUNNING` → `RUNNING`) persists the run as `running`.
3. **No continuation when no sequencer observes** — the cancel command only mutates the attempt. On replay,
   `runSessionLocked`'s prelude turns a `RUNNING` step with a terminal attempt into `READY` (`hasFinalizedAttempt`), then
   `terminalAgentExecution` classifies the interrupted attempt as `AgentFailed(AGENT_INTERRUPTED)` → `failed`, never `cancelled`; and
   nothing enqueues that replay in the first place.
4. Occupancy: `CapabilityExecutionService.releaseAgentWorktreeIfResultAccepted` only releases with an accepted result → a cancelled
   attempt keeps its occupancy forever.

## 5. Design principle

**The sequencer stays the only writer of step/run status.** The cancel command never writes the projection (it would race the
sequencer's in-memory progress and its instance-revision CAS). It (a) kills the runtime with an identity, (b) seals the attempt as
today, (c) releases the occupancy when the kill is acknowledged, (d) enqueues a durable continuation. The sequencer recognises a
*user-cancelled attempt* (latest attempt of the step is `INTERRUPTED` with `failureCode == "USER_CANCELLED"`) at two points — the
fencing catch and the replay prelude — and seals the step `cancelled`; a cancelled step stops all further dispatch and makes the run
`cancelled`.

## 6. Scoped change (backend, file by file)

### 6.1 `factory/factory-service/src/main/kotlin/io/whozoss/factory/adapter/agentos/AgentRuntimeAdapter.kt`
Add an identity-carrying overload, defaulted so every existing adapter/fake stays source-compatible and fail-closed:
```kotlin
/** 5b. Authenticated controlled interruption. True only when the runtime acknowledged the kill. */
fun interrupt(caseId: String, reason: String, externalUserId: String?): Boolean {
    interrupt(caseId, reason)
    return false
}
```

### 6.2 `.../adapter/agentos/DefaultAgentOsExecutionAdapter.kt`
- `postKill(caseId: String, externalUserId: String?): Boolean`: identity = `externalUserId?.takeIf { it.isNotBlank() }` ?:
  `executions.values.firstOrNull { it.caseId == caseId }?.externalUserId`; set `X-External-User-Id` when non-blank; return `true` on
  2xx; on any exception `logger.warn(e) { "AgentOS kill of case $caseId failed (status=…)" }` (include the HTTP status when it is a
  `RestClientResponseException`) and return `false`. Never throws.
- Override `interrupt(caseId, reason, externalUserId)`: record `interruptReasons[caseId] = reason`, return `postKill(caseId, externalUserId)`.
- `interrupt(caseId, reason)` → `interrupt(caseId, reason, null)`; `kill(caseId)` → `postKill(caseId, null)` (record fallback now
  authenticates the escalation and shutdown kills too). Update the KDoc of `postKill`.

### 6.3 `.../agentattempt/service/BridgeCancellationService.kt`
- New optional constructor deps (nullable, defaulted to `null`, keeping `BridgeCancellationService(attempts, adapter)` valid for tests):
  `workflowRepository: WorkflowRepository? = null`, `worktreeOccupancyService: WorktreeExecutionOccupancyService? = null`.
- `requestCancel(..., reason, actorId: String? = null)`:
  - identity = persisted workflow actor `instance.instance["controllerRequest"]["actorId"]` (same rule as
    `CapabilityExecutionService.resolveExternalUserId`; it created every case of the family and holds ADMIN) ?: `actorId` (caller).
  - `val killed = adapter.interrupt(attempt.caseId, reason, identity)` (replaces `adapter.interrupt(caseId, reason)`).
  - reconcile + durable `attempts.requestCancel(...)` unchanged.
  - After the durable cancel: if `killed`, re-read the attempt and, when the 4 occupancy fields are present,
    `worktreeOccupancyService?.releaseOwned(WorktreeExecutionOccupancyHandle(environmentRef ?: "", identity, scope, kind, owner, generation))`
    inside `runCatching` + WARN log (mirror `releaseAgentWorktreeIfResultAccepted`). Not killed → retained (fail-closed).
  - Add `killAcknowledged: Boolean` to `CancellationOutcome` (false on idempotent replay).
- Idempotent replay path unchanged (no second kill).

### 6.4 `.../workflow/web/WorkflowController.kt` — `cancelAttempt`
- Pass `caller.actorId` to `requestCancel`.
- After the outcome (also on an idempotent replay, which heals already-stuck runs): enqueue a durable continuation
  `sessionRunSubmissionService.submit(caller.scope, caller.namespaceId, workflowId, repoRoot, "attempt-cancelled:$attemptId", null)`
  where `repoRoot = resolveRepoRoot(caller.namespaceId, user.userId) ?: sessionProperties.defaultRepoRoot` (same resolution as
  `runInternal`). If no repo root resolves, skip the enqueue with a WARN (the cancellation itself is already committed); wrap the
  enqueue in `runCatching` so it never turns a committed cancellation into a 500.
- Response: add `"killAcknowledged"` to the returned map (additive; the cockpit ignores unknown fields).

### 6.5 `.../capability/CapabilityExecutionService.kt`
Add one public read helper (no other change):
```kotlin
/** The latest attempt of the step was explicitly cancelled by a user (Stop). */
fun isUserCancelled(scope: TenantScope, namespaceId: String, workflowId: String, stepId: String): Boolean {
    val latest = durableAgentAttemptService.findLatestForStep(scope, namespaceId, workflowId, stepId) ?: return false
    return latest.status == AgentAttemptStatus.INTERRUPTED && latest.failureCode == USER_CANCELLED
}
```
with `const val USER_CANCELLED = "USER_CANCELLED"` in the companion; use the same constant in `BridgeCancellationService`
(replace the string literal) and as the default of `DurableAgentAttemptService.requestCancel` if convenient.

### 6.6 `.../workflow/service/SessionRunService.kt`
1. New private `recordStepCancellation(scope, ns, wf, step, expectedRevision, statuses)`: in `newTransaction { }` append a
   `session-step` evidence (`outcome = cancelled`, facts `stepId`, `status=cancelled`, `code=USER_CANCELLED`, `attemptId` of the latest
   attempt, `executionId`), `transition(..., CANCELLED, ...)`, `setStatus(..., CANCELLED, ...)` (it already stamps `completedAt`,
   records the outcome ledger and publishes SSE). Same `runCatching`/fallback shape as `recordStepFailure`.
2. `executeStep`, `catch (fenced: AttemptLeaseFencingException)`: if
   `capabilityExecutionService.isUserCancelled(scope, ns, wf, step.id)` → `recordStepCancellation(...)`; `return WorkflowStatuses.CANCELLED`.
   Otherwise keep the existing hand-off behaviour (`return null`).
3. Replay prelude in `runSessionLocked` (loop over agent steps): **before** the `canReplayOrResume` evaluation, if the step is
   `RUNNING`, `WAITING_HUMAN`, `READY` or `PENDING`-with-attempt and `isUserCancelled(...)` → `recordStepCancellation(...)` and
   `continue` (never set it `READY`). Simplest correct guard: status in `{RUNNING, WAITING_HUMAN, READY}` && `isUserCancelled`.
4. Dispatch guard in the `while` loop, right after `applyEvaluation(...)`: `if (statuses.statuses.values.any { it == WorkflowStatuses.CANCELLED }) return@run`
   — no new step (independent branch, later continuation) is ever dispatched after a user Stop.
5. `persistProgressProjection` status `when`: add, right after the correction `waiting_human` branch and **before** the
   `executions.isNotEmpty() && FAILED -> RUNNING` ledger branch:
   `progress.statuses.values.any { it == CANCELLED } && progress.statuses.values.none { it == RUNNING } -> WorkflowStatuses.CANCELLED`.

### 6.7 `.../workflow/domain/SessionSequencer.kt` — `terminalStatus`
First rule: `if (values.any { it == CANCELLED } && values.none { it == RUNNING }) return WorkflowStatuses.CANCELLED`. Update the KDoc.
(`CANCELLED` is already in `BLOCKING`, so dependents become `blocked`; `WorkflowStatuses.TERMINAL` already contains it.)

### Out of scope (propose separate tickets)
- Post-kill `adapter.reconcile(caseId)` and other adapter reads still go unauthenticated after a Factory restart (no in-memory
  record) → `reconciledVerdict` may be `null`. Proposal: persist/forward the identity for every adapter call.
- Independent `READY` branches stay displayed as `ready` after a Stop (not dispatched). A "cancel whole run" command that seals them
  `cancelled` is a separate feature.
- Frontend: a dedicated "stopped" chip instead of `failed` for a `cancelled` run.

## 7. Contract

No frontend change. HTTP contract of `POST .../attempts/{attemptId}/cancel` is unchanged except one additive response field
`killAcknowledged: boolean`. Projection/step status may now be `cancelled` — already handled by the cockpit
(`mapWorkflowStateToRunStatus('cancelled') → 'failed'`, `resolveStepState` keeps `cancelled`, Stop hidden without an active attempt).
AgentOS contract used: `POST /api/cases/{caseId}/kill` with header `X-External-User-Id: <workflow actor>`.

Implementation order: 6.1 → 6.2 (+ adapter tests) → 6.5 → 6.7 → 6.6 (+ sequencer tests) → 6.3 → 6.4 (+ HTTP test).
