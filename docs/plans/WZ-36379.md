# WZ-36379 — Stopping a workflow run does not stop AgentOS agents and leaves the run RUNNING

- Jira: https://whoz.atlassian.net/browse/WZ-36379 (Bug)
- Branch: `work/forge/WZ-36379-stop-run-kills-agents` → base `workstream/forge/master`
- Sides concerned: **backend and frontend** (factory-service, factory-cockpit). Backend first, frontend second (section 7).
- Risk level: **medium-high** (concurrency between the cancel command and the sequencer, authorization delegated to AgentOS,
  worktree release).
- Revision 3: corrected after the second review of PR #1770 (section 10). Product decisions taken by the reporter on 2026-11-25
  (B. Valdes): **worktree released once the kill is proven**, **Stop allowed to anyone AgentOS lets kill the case**.

## 1. Expected outcome

Clicking **Stop** on a running Factory run kills the AgentOS case and all its active descendant sub-cases, the step and the run leave
`running` for `cancelled`, the worktree occupancy is released as soon as AgentOS proves the case is killed, and the user is told when
the stop is refused or not confirmed (and can retry it).

Observed: `POST /api/factory/workflows/{workflowId}/attempts/{attemptId}/cancel` moves the attempt to `interrupted / USER_CANCELLED` but
the case keeps running and the step and run stay `running` forever (runs `45717d0c-ede8-3ea9-b8e1-cf01447dc6bf`,
`ddcb8f34-35af-317f-bc8d-8c8b0060a0d7`). Reproduction steps: complete.

## 2. Acceptance criteria

1. (ticket) Stop sends an authenticated kill (`POST /api/cases/{caseId}/kill` + `X-External-User-Id`); AgentOS kills the case and its
   active descendants.
2. (ticket) Step and run leave `running` for `cancelled` (projection and cockpit); a fragment of a parent Run makes the parent Run
   `cancelled`.
3. (ticket, decision 1A) The worktree occupancy of the cancelled attempt is released once the kill is **proven**: kill acknowledged
   (2xx) **and** AgentOS reports the case `KILLED`. Until then it is retained, and a periodic sweep releases it as soon as the proof is
   available. The per-workflow sequencer lock and the continuation are freed.
4. (decision 2A) Anyone AgentOS allows to kill the case (`Case DELETE`: the run owner, a namespace admin…) can stop the run. A refused
   kill returns `403 STOP_NOT_AUTHORIZED` and changes nothing. The cockpit shows it.
5. (derived) A refused or unconfirmed kill never leaves the run stuck: the step and run are still sealed `cancelled` for the owner, the
   cockpit shows "stop not confirmed" and offers **Stop** again, which re-sends the kill.
6. (derived) A Stop is final: dependents `blocked`, nothing dispatched afterwards; a cancelled run cannot be retried (as WZ-36045).
7. (derived) Runs already stuck are sealed by the next `runSession`, even when the workspace precheck would fail.
8. (derived) Deterministic outcome whichever side wins the race between the cancel command and the sequencer.

## 4. Root cause

1. `DefaultAgentOsExecutionAdapter.postKill` sent no `X-External-User-Id` and swallowed errors (derived from the code: `killCase`
   requires `Case DELETE`).
2. The durable cancel rotates the owner token; the sequencer's finalize is fenced, `executeStep` returns `null`, step and run stay `running`.
3. Nothing enqueues a continuation; a replay would classify the attempt `failed`.
4. Kill-before-cancel ordering let the sequencer finalize `failed` before the cancel.
5. (review 2) The sequencer stays blocked in the SSE observation as long as the case runs, so a refused kill keeps the run `running`.

## 5. Design

The sequencer stays the only writer of step/run status. A user stop is recognised from **durable facts of the attempt**
(`INTERRUPTED/USER_CANCELLED`, bound to the current execution), whichever side commits first.

### 5.1 Authorization (2A) and ordering
`requestCancel(..., actorId)`:
1. Load the attempt. Terminal and not `INTERRUPTED` → `409 ATTEMPT_INVALID_TRANSITION`, nothing sent. Stale `expectedRevision` →
   `409 REVISION_CONFLICT`, nothing sent (both checked before any remote call).
2. **Caller is the run owner** (`controllerRequest.actorId`): durable cancel first, then kill with the owner identity (order already
   approved).
3. **Caller is someone else**: the kill, sent with the **caller** identity, is the authorization check, so it goes first:
   - `REFUSED` (401/403) → `403 STOP_NOT_AUTHORIZED`, nothing written, interrupt intent removed;
   - `UNREACHABLE` (no response, 5xx) → `503 STOP_RUNTIME_UNAVAILABLE`, nothing written;
   - `ACKNOWLEDGED` → durable cancel (an already `INTERRUPTED/USER_CANCELLED` attempt is accepted as idempotent, see 5.2).
4. Then for both: `adapter.abandonObservation(caseId)`, post-kill `caseStatus`, occupancy release if proven (5.3), `agent-stop` evidence.

### 5.2 Race, whichever side wins
- Cancel commits first (owner): the sequencer is fenced → `recordStepCancellation` (unchanged).
- Kill lands first (non-owner): the interrupt reason is recorded as `USER_CANCELLED: <reason>` before the kill. When the sequencer
  derives `Interrupted` from that reason, `finalizeAgentAttempt` finalizes `INTERRUPTED` with `failureCode = USER_CANCELLED` and returns a
  new `CapabilityOutcome.AgentCancelled`, classified `CANCELLED` → `recordStepCancellation`. The following durable cancel finds the
  attempt already `INTERRUPTED/USER_CANCELLED` and is idempotent.
- Sequencer finalizes on its own first: 409 before any kill (unchanged).

### 5.3 Kill outcome, proof and retry
- `postKill` returns `KillResult { ACKNOWLEDGED, REFUSED, UNREACHABLE }`. Failures are logged at WARN **without** stack trace (case id,
  status); the stack trace at DEBUG.
- **Unblocking the sequencer**: `abandonObservation(caseId)` makes `AgentOsSseClient.observe` return
  `Interrupted("USER_CANCELLED: observation abandoned")` within one poll (≤ 1 s); the sequencer then hits the fenced finalize and seals
  the step. So the run leaves `running` even when the kill was refused or AgentOS is down.
- **Proof of kill**: new `adapter.caseStatus(caseId, externalUserId): String?` (`GET /api/cases/{id}` → `status`). The root case is killed
  by AgentOS after its descendants, so `KILLED` on the root is the proof.
- `agent-stop` evidence per Stop (step-scoped): `attemptId`, `actorId`, `killResult`, `caseStatus`, `killProven`.
- **Retry**: Stop on an `INTERRUPTED/USER_CANCELLED` attempt is no longer a silent no-op: it re-runs 5.1 step 3/4 (authorization by kill
  for non-owners), re-sends the kill when the case is not `KILLED`, releases the occupancy when proven, records a new `agent-stop`.
- **Read model**: when the latest `agent-stop` of the latest attempt has `killProven=false`, `workflowActions` emits blocker
  `AGENT_KILL_UNCONFIRMED` and a `cancel_attempt` action labelled "Retry stop" (attempt revision). The cockpit already derives
  `activeAttemptId` from `cancel_attempt` first.

### 5.4 Occupancy (1A)
- Immediate: released by `BridgeCancellationService` when `killProven`.
- Eventual: `BridgeRecoveryWorker.releaseAcceptedTerminalOccupancies` also releases a terminal attempt with occupancy that is
  `INTERRUPTED/USER_CANCELLED` when `caseStatus(caseId, persisted actorId) == "KILLED"` (bounded by the existing page/budget).
- Until released, a run on the same physical worktree is deferred (`AGENT_WORKTREE_OCCUPIED` / `WORKTREE_OCCUPIED`), which is the
  intended fail-closed behaviour while the kill is not proven.

### 5.5 Scope of the `cancelled` status
Producers of a `cancelled` **step state** (`workflow_step_states`): only `SessionRunService.recordStepCancellation` (user Stop). The
governed `POST /transitions` writes `instance.steps` of governed instances, not step states. The rules "a cancelled step ends the run"
(dispatch guard, `terminalStatus`, `persistProgressProjection`) are therefore user-Stop rules in practice; they are documented as
"any cancelled step state ends the run". `sealedByUserStop` is renamed `runCancelled`. Builder confirms by search that no other writer
exists and reports it; a test pins the rule.

### 5.6 Prelude cost and robustness
`sealUserCancelledSteps` only runs when an agent step is `RUNNING` or `WAITING_HUMAN`; it loads the workflow attempts **once**
(`findByWorkflow`), checks `status == INTERRUPTED && failureCode == USER_CANCELLED` **before** parsing the envelope, and an unreadable
envelope yields "not bound" with a WARN, never an exception.

## 7. Contract

`POST /api/factory/workflows/{workflowId}/attempts/{attemptId}/cancel`, body unchanged (`namespaceId`, `expectedRevision`, `reason`).
- 200: `{ workflowId, attemptId, stepId, status, revision, idempotent, reconciledVerdict, killResult: "ACKNOWLEDGED"|"REFUSED"|"UNREACHABLE", killProven: boolean }`
  (`killAcknowledged` removed: unused).
- 403 `STOP_NOT_AUTHORIZED` (AgentOS refused the caller's kill, nothing changed); 409 `ATTEMPT_INVALID_TRANSITION` / `REVISION_CONFLICT`;
  503 `STOP_RUNTIME_UNAVAILABLE` (non-owner, AgentOS unreachable, nothing changed).
- `/actions`: blocker `AGENT_KILL_UNCONFIRMED` + `cancel_attempt` "Retry stop".

Order: backend (adapter → SSE client → capability → sequencer → cancellation → recovery → actions → controller → OpenAPI), then cockpit.
