# GH-1717 — Show the cost-threshold confirmation in the chat composer, like a question

Ticket: https://github.com/whoz-oss/coday/issues/1717 (GitHub issue, label `enhancement`; no Jira ticket)
Branch: `work/forge/issue-1717-cost-pause-in-composer` → base `workstream/forge/master`
Routes: **frontend** only. Risk: **low to medium**.

Supersedes the plan of the closed draft PR #1757 (`feature/GH-1717-cost-pause-in-composer`), which used a branch name
outside the `work/forge/*` convention of the forge workstream. The design is unchanged and was re-checked against the
current `workstream/forge/master` (137ab771b).

## 1. Expected outcome

When a run reaches its cost threshold, the request to continue (double the threshold) or stop appears in the chat
composer area, presented and focused like any other question to the user, instead of only in the usage strip at the
top of the case.

Type: improvement, not a bug. Current behaviour works as designed but is hard to notice: the usage strip
(`<details>` in `agentos-case-usage`) pops open above the timeline while the composer just looks disabled and the run
looks slow. Reproduction is complete: set a tiny *Cost limit* on a case (header edit) and send a message.

## 2. Acceptance criteria

From the ticket:
- **AC1**: when a run is paused at its cost threshold, the continue/stop decision is shown in the chat input
  (composer) area.
- **AC2**: it reads like any other request addressed to the user (ticket title: "as query to the user like any other
  message").

Derived (flagged, mine):
- **AC3 (derived)**: decision semantics unchanged. *Continue · double threshold to X* calls
  `POST /api/cases/{id}/run-cost/continue` with `expectedThreshold = limit.threshold`; *Stop* calls
  `POST /api/cases/{id}/run-cost/stop`. Parent / delegated pauses, `canContinue === false`, hidden linked pause
  (`paused && pausedCases.length === 0`) and threshold `0` keep their current texts and buttons.
- **AC4 (derived)**: the top usage strip becomes a read-only readout: it keeps the *Paused · cost threshold reached*
  title, the `usage--paused` accent and the figures, but holds no decision buttons and is no longer forced open on
  pause. Only one place offers the decision.
- **AC5 (derived)**: when the pause appears, focus moves to the first enabled action of the card, with the same
  non-intrusive guards as `focusQuestionControls` (no move during a text selection or while typing in another field).
  The card is announced (`role="alert"` on its lead line).
- **AC6 (derived)**: no extra polling: the strip and the card share one run-cost poll per case.
- **AC7 (derived)**: nothing shown when usage tracking is disabled, as today.

Key files:

  `total`, `error`, `saving`; navigation reset effect; polling effect (`merge(of(true), answers, timer(2000,2000))` +
  `exhaustMap`, cancelled while `saving`); `loadUsage`, `applyUsage`; `continue(limit)` (then `getRunCost` +
  `caseState.refreshCaseThreshold`); `stop()`.
- `libs/agentos-ui/src/lib/components/case-usage/case-usage.component.html` — readout + the pause decision block
  (per-limit lines, Continue / Continue with updated threshold, permission text, Stop) and `[open]` bound to pause.
- `libs/agentos-ui/src/lib/components/case-usage/case-usage.component.spec.ts` — ~20 tests (polling, slow response,
  failed poll, navigation, aggregate per answer, continue / stop / parent pause).
- `libs/agentos-ui/src/lib/components/case-chat/case-chat.component.html` — `<agentos-case-usage>` at l.139 under the
  header; composer `.case-chat__composer` at l.428; inline questions rendered with `agentos-question-panel
  variant="inline"` inside `[data-question-controls]`.
- `libs/agentos-ui/src/lib/components/case-chat/case-chat.component.ts` — `providers: [ComposerAttachmentsService,
  ComposerAutocompleteService, VoiceRecorderService]` (l.183, component-scoped state pattern); `canAttach =
  exchangeState.canWriteCase` (l.218); focus effect on `pendingQuestionId` (l.500-510) and `focusQuestionControls`
  (l.787) with its guards (`hasActiveSelection`, other field focused).
- Backend (unchanged): `agentos/agentos-service/.../usage/RunCostController.kt`, `RunCostService.kt`; generated client
  `libs/agentos-api-client/src/lib/model/run-cost-dto.ts` (`RunCostDto { paused, runCostThreshold, pausedCases:

Cause of the poor visibility: the decision UI is coupled to the header readout component, placed above the scrolling
timeline, far from the composer and from where questions appear.

Regression risk areas: the subtle poll lifecycle (saving cancels polling, navigation resets, `exhaustMap` absorbs slow
responses) must move verbatim; the question focus effect of `case-chat` must not be disturbed.

## 5. Scoped change (frontend only)

Principle: split state from presentation. One component-scoped state service owns the poll and the decision; the
existing strip keeps the figures; a new composer card holds the decision.

1. **New** `libs/agentos-ui/src/lib/services/case-run-cost-state.service.ts` (`@Injectable()`, no `providedIn`).
   - Move verbatim from `CaseUsageComponent`: `run`, `total`, `error`, `saving`, the two effects, `loadUsage`,
     `applyUsage`, `continue(limit)`, `stop()`.
   - Inputs become writable signals set by the host: `caseId`, `canWrite`, `running` (e.g. `bind(caseId, canWrite,
     running)` or three `set*` methods). The **owner is `CaseChatComponent`** (it provides the service and feeds it
     from its own inputs in an effect), so the poll lives exactly once per chat.
   - Add computed `paused = !!run() && (run()!.paused || run()!.pausedCases.length > 0)`.
2. **Edit** `libs/agentos-ui/src/lib/components/case-usage/case-usage.component.{ts,html,scss}`.
   - Inject `CaseRunCostStateService`; drop own state, effects and actions. Keep the `caseId` input for the
     "Conversation / Delegated" labels only if still needed; `canWrite` / `running` inputs can be removed together with
     the binding in `case-chat.component.html`.
   - Template: keep settings loading/error/retry, summary figures, paused title and accent, body texts (delegated
     work, conversation breakdown, live tokens, unknown price warning) and the refresh error. **Remove** the decision
     block ("The next request is waiting…" paragraph through the Stop button) and the `[open]` binding.
3. **New** `libs/agentos-ui/src/lib/components/cost-pause-card/cost-pause-card.component.{ts,html,scss,spec.ts}`
   (selector `agentos-cost-pause-card`, OnPush, standalone).
   - Injects `CaseRunCostStateService` and `UsageConfigurationService`; renders nothing unless
     `configuration.enabled() && state.paused()`.
   - Content: lead line with `role="alert"` ("Cost threshold reached: {cost} consumed. Continue?"), then the decision
     markup moved from `case-usage.component.html` with every branch kept, then `state.error()`.
   - Look: same card tokens as the inline question (`case-chat__question-controls` / `agentos-question-panel`
     inline). Root element carries `data-cost-pause-controls` for focusing.
4. **Edit** `libs/agentos-ui/src/lib/components/case-chat/case-chat.component.ts`.
   - Add `CaseRunCostStateService` to `providers`, `CostPauseCardComponent` to `imports`; effect feeding the service
     with `caseId`, `canAttach()`, `isRunning()`.
   - Focus effect: when `paused()` turns true (rising edge), `afterNextRender` → focus
     `[data-cost-pause-controls] button:not(:disabled)` under the guards of `focusQuestionControls`. Extract the guard
     part into a small private helper shared by both; no other behaviour change.
5. **Edit** `libs/agentos-ui/src/lib/components/case-chat/case-chat.component.html`.
   - Render `<agentos-cost-pause-card />` as the first child of `.case-chat__composer` (above autocompletes and
     textarea). `<agentos-case-usage>` stays under the header.
6. **Specs**
   - Move decision tests from `case-usage.component.spec.ts` to `cost-pause-card.component.spec.ts` (exact doubled
     threshold, single submit while pending, parent pause, read-only parent, hidden linked pause, read-only viewer, stop
     targets the viewed case).
   - Keep polling / refresh / figure tests in `case-usage.component.spec.ts`, providing the real service in the test
     host.
   - Add `case-run-cost-state.service.spec.ts` only for logic not reachable through the component specs.

Out of scope (separate tickets if wanted): a persisted timeline event for the pause (new `CaseEvent` type, backend);
Factory cockpit cost actions; any change to the doubling rule.

## 6. Contract

Frontend only: no backend change, no new API. Existing endpoints `GET /api/cases/{caseId}/run-cost`,
`POST /api/cases/{caseId}/run-cost/continue {expectedThreshold}`, `POST /api/cases/{caseId}/run-cost/stop` and the
generated `RunCostDto` / `PausedCostDto` types.

## 7. Verification

New tests (fail before, pass after):
- `cost-pause-card`: paused run renders the alert lead line, `Continue · double threshold to 20.00` and `Stop`; Continue
  calls `continueCostRunRunCost('case-a', { expectedThreshold: 10 })` once; nothing rendered when not paused or usage
  disabled.
- `case-usage`: when paused, shows *Paused · cost threshold reached* and the figures, has no Continue/Stop button and
  `details.open` is false.
- `case-chat`: the card is a descendant of `.case-chat__composer`; focus lands on Continue when the pause appears and
  the user is not typing elsewhere.

Must stay green: carried-over `case-usage.component.spec.ts` cases (polling start/stop, slow response, failed poll
recovery, navigation cancel, aggregate per answer, disabled usage, threshold separation) and
`case-chat.component.spec.ts` (question focus included).

Commands: `pnpm nx run-many -t lint test -p agentos-ui`, then `pnpm nx affected -t lint test`.

Manual check: case *Cost limit* = 0.001, send a message → card above the composer, focus on Continue; Continue → header
`max …` doubles and the run resumes; Stop → run ends. Also a delegated sub-case paused by its parent, and a viewer
without edit rights.

Neighbouring behaviours: composer stays disabled during the pause; question focus unaffected; header threshold badge
updates after Continue (`refreshCaseThreshold`).

Risk: **low to medium** — UI-only, no API change, but the polling logic moves and must be carried verbatim with its
tests.
