# GH-1717 — Show the cost-threshold confirmation in the chat composer, like a question

Ticket: https://github.com/whoz-oss/coday/issues/1717 (enhancement)
Branch: `feature/GH-1717-cost-pause-in-composer` → base `workstream/forge/master`
Routes: **frontend** only. Risk: **low to medium**.

## 1. Expected outcome

A run that reaches its cost threshold must ask the user to decide in the place they are already looking, which is the
chat input area. Today the request appears only in the usage strip at the top of the case, so users take it for a slow
run.

Type: improvement (not a bug). The current behaviour works as designed but is hard to notice. The reporter describes
the trigger (a run hits its cost limit), so the situation is easy to reproduce: set a low *Cost limit* on a case and
send a message.

## 2. Acceptance criteria

From the ticket:
- **AC1**: when a run is paused at its cost threshold, the request to continue ("double threshold") or stop is shown in
  the chat input (composer) area, not only at the top of the screen.
- **AC2**: it reads like any other request addressed to the user (ticket title: "as query to the user like any other
  message"), so it looks and behaves like an agent question.

Derived (my own, to keep current behaviour):
- **AC3 (derived)**: the existing decision semantics do not change. *Continue · double threshold to X* calls
  `POST /api/cases/{id}/run-cost/continue` with `expectedThreshold`. *Stop* calls `POST …/run-cost/stop`. Parent and
  delegated pauses, `canContinue === false`, a hidden linked pause and a threshold of 0 keep exactly the messages and
  buttons they have today.
- **AC4 (derived)**: the top usage strip stays as a read-only readout (this run / threshold / conversation / tokens). It
  still shows the *Paused · cost threshold reached* title, but it holds no decision buttons any more, and it no longer
  forces itself open when paused. Only one place offers the decision.
- **AC5 (derived)**: when the pause appears, keyboard focus moves to its first enabled action, under the same
  non-intrusive guards as `focusQuestionControls`: no move during an active text selection or while the user types in
  another field. The card is announced (`role="alert"` or an `aria-live` region).
- **AC6 (derived)**: no new polling. The header readout and the composer card share one run-cost poll per case.
- **AC7 (derived)**: nothing is shown when usage tracking is disabled, the same as today.

## 3. Related tickets and location clues

- UI words in the ticket: "cost limit" (the header edit placeholder `Cost limit`), and "modal at the top of the
  screen" (actually the `<details>` usage strip rendered by `agentos-case-usage`, opened automatically on pause).
- Related: #1715 (tool groups and live activity, recent changes to `case-chat`). No duplicate found.
- Factory cockpit (`apps/factory-cockpit/.../action-bar`) has its own `continue_cost`/`stop_cost` actions. **Out of
  scope**: the ticket is about the AgentOS chat.

## 4. Code analysis (read-only)

Key files:
- `libs/agentos-ui/src/lib/components/case-usage/case-usage.component.{ts,html,scss,spec.ts}`: owns everything today.
  It polls `RunCostControllerService.getRunCost` every 2 s while running, refreshes the aggregate on agent answers,
  renders the strip, and holds the pause decision (`continue(limit)`, `stop()`, `saving`, `error`). The `[open]`
  binding on `<details>` makes the strip pop open on pause. That is the "modal at the top".
- `libs/agentos-ui/src/lib/components/case-chat/case-chat.component.html`: mounts `<agentos-case-usage>` right under
  the header, outside the messages and the composer. The composer is `.case-chat__composer`. Questions are rendered
  inline in the timeline through `agentos-question-panel variant="inline"` (`.case-chat__question-controls`), with
  focus moved by `pendingQuestionId` + `focusQuestionControls`.
- `libs/agentos-ui/src/lib/components/case-chat/case-chat.component.ts`: `isRunning` stays true while the run is
  gated, which is why the textarea is disabled. The user only sees a disabled composer and a running indicator, and
  this is the confusion the reporter describes.
- Backend contract (unchanged): `agentos/agentos-service/.../usage/RunCostController.kt` and `RunCostService.kt`.
  `RunCostDto { paused, runCostThreshold, pausedCases: PausedCostDto[{caseId, cost, threshold, ancestor,
  canContinue}] }`. The generated client is `libs/agentos-api-client`.

Root cause of the poor visibility: the decision UI is coupled to the header readout component. It is placed above the
scrolling timeline, away from the composer, the agent activity line and the place where questions appear.

Patterns to follow:
- Component-scoped state services provided by `CaseChatComponent` (`ComposerAttachmentsService`,
  `ComposerAutocompleteService`, `VoiceRecorderService`): `providers: [...]` on the chat, `inject()` in children.
- The question presentation (`agentos-question-panel`, `case-chat__question-controls`) for the look of a request
  addressed to the user.

Regression risk areas: `case-usage.component.spec.ts` has about 20 tests, several on continue/stop/parent pause. The
poll lifecycle has subtle rules: `saving` cancels polling, navigation resets, `exhaustMap` absorbs slow responses.
These rules must keep working once the logic moves.

## 5. Scoped change (frontend only)

Principle: split *state* from *presentation*. One component-scoped state service owns the run-cost poll and the pause
decision. Two components consume it: the existing header readout, which keeps only the figures, and a new composer
card, which holds the decision.

1. **New** `libs/agentos-ui/src/lib/services/case-run-cost-state.service.ts` (`@Injectable()`, not `providedIn`).
   - Move the logic out of `CaseUsageComponent` unchanged: signals `run`, `total`, `error`, `saving`; the polling
     effect, now driven by an `activate(caseId, running: Signal<boolean>)` call or by input signals that the host sets;
     `continue(limit)`; `stop(canWrite)`; and the navigation reset.
   - Add the computed values `paused = run()?.paused || run()?.pausedCases.length > 0` and `pausedCases`.
   - Keep the guards exactly as they are: `configuration.enabled()`, `limit.canContinue`, `saving`, and
     `caseState.refreshCaseThreshold(limit.caseId)` after continue.
2. **Edit** `case-usage.component.ts/.html/.scss`.
   - Inject `CaseRunCostStateService` instead of owning state. Keep the inputs `caseId`, `canWrite` and `running`; the
     component forwards them to the service, or the chat drives the service directly. The implementer chooses one
     owner and documents it.
   - Template: keep the settings loading/error/retry block, the summary figures, the *Paused · cost threshold reached*
     title, the `usage--paused` accent and the body text (delegated work, conversation breakdown, live tokens, unknown
     price warning). **Remove** the pause decision block (per-limit lines, buttons, permission texts, Stop) and the
     `[open]` binding on pause.
3. **New** `libs/agentos-ui/src/lib/components/cost-pause-card/cost-pause-card.component.{ts,html,scss,spec.ts}`
   (selector `agentos-cost-pause-card`).
   - Inputs: `caseId`, `canWrite`. It injects `CaseRunCostStateService`. It renders nothing unless
     `configuration.enabled() && state.paused()`.
   - Content: the pause markup moved from `case-usage.component.html` with every existing branch kept
     (Parent/Conversation/Delegated run label, `limit.threshold > 0` vs "Set a positive threshold…", `canContinue` false
     text, hidden linked pause text, Stop when `canWrite`). Add a short lead line for the agent, for example
     "Cost threshold reached: {{cost}} of {{threshold}}. Continue?", and the `state.error()` message.
   - Look: the question-panel style (same bubble/card tokens as `case-chat__question-controls`), with
     `role="alert"` on the lead line. It carries a `data-cost-pause-controls` attribute for focusing.
4. **Edit** `case-chat.component.ts`.
   - Add `CaseRunCostStateService` to `providers` and `CostPauseCardComponent` to `imports`.
   - Add a focus effect: when the service's `paused()` turns true, run `afterNextRender` → focus
     `[data-cost-pause-controls] button:not(:disabled)`. Reuse the guards of `focusQuestionControls`, and extract a
     small private helper if needed, with no other behaviour change.
5. **Edit** `case-chat.component.html`. Render `<agentos-cost-pause-card [caseId]="caseId" [canWrite]="canAttach()" />`
   inside `.case-chat__composer`, as its first child, above the autocompletes and the textarea. It is always visible
   and needs no scrolling. The existing `<agentos-case-usage>` stays where it is.
6. **Specs**
   - Move the decision tests from `case-usage.component.spec.ts` to `cost-pause-card.component.spec.ts`: exact doubled
     threshold, single submit while pending, parent pause, read-only parent, hidden linked pause, read-only viewer, stop
     targets the child only.
   - Keep the polling, refresh and figure tests in `case-usage.component.spec.ts`, providing the real service.
   - Add a test that `case-usage` renders **no** button and no forced `open` when paused.
   - Add a small `case-run-cost-state.service.spec.ts` only if a test is hard to carry over. Otherwise the two component
     specs cover the service.

Out of scope, possible follow-ups:
- An extra timeline entry for the pause (a persisted backend event). It would need a new `CaseEvent` type. Separate
  ticket if wanted.
- Factory cockpit cost actions.
- Any change to the doubling rule.

## 6. Contract

The frontend only. There is no backend change and no new API. The card uses the existing endpoints
`GET /api/cases/{caseId}/run-cost`, `POST …/run-cost/continue {expectedThreshold}` and `POST …/run-cost/stop`, and the
generated `RunCostDto` / `PausedCostDto` types.

## 7. Verification

New tests (fail before, pass after):
- `cost-pause-card`: renders the lead line, `Continue · double threshold to 20.00` and `Stop` for a paused run.
  Clicking Continue calls `continueCostRunRunCost('case-a', {expectedThreshold: 10})` once. Nothing is rendered when
  not paused or when usage is disabled.
- `case-usage`: when paused, the strip shows *Paused · cost threshold reached* and the figures, has **no** `button`
  element (apart from the settings retry), and the `details` is not forced open.
- `case-chat`, through the real template or the service: the card is a descendant of `.case-chat__composer`.

Tests that must stay green: all carried-over cases of `case-usage.component.spec.ts` (polling start and stop, slow
response, failed poll recovery, navigation cancel, aggregate refresh per answer, disabled usage, threshold separation)
and `case-chat.component.spec.ts`.

Commands:
`pnpm nx run-many -t lint test -p agentos-ui` (use the project name from `libs/agentos-ui/project.json`), then
`pnpm nx affected -t lint test`.

Manual check: set a case *Cost limit* to a tiny value (for example 0.001) and send a message. Check that the card
appears above the composer with focus on Continue. Continue: the threshold doubles in the header (`max …`) and the run
resumes. Stop: the run ends. Also check a delegated sub-case paused by its parent, and a viewer without edit rights.

Neighbouring behaviours to check: the composer stays disabled during the pause (unchanged). The question focus effect
is not disturbed. The header `max …` threshold badge updates after Continue (`refreshCaseThreshold`).

Risk: **low to medium**. It is a UI-only refactor with no API change, but the subtle polling logic moves, so it must be
moved verbatim and covered by the carried-over tests.
