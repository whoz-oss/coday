# WZ-36391 — Remove "Ask supervisor" and enable "Conversation" on dashboard run cards

Jira: https://whoz.atlassian.net/browse/WZ-36391 (User Story, epic WZ-36044 "FP - Forge - Feb 2027")
Branch: `work/forge/WZ-36391-run-card-conversation-link` → PR base `workstream/forge/master`
Sides: **frontend only** (`apps/factory-cockpit`). No backend or API contract change.

## 1. Expected outcome

On the Workstreams dashboard, each run card no longer shows any "Ask supervisor" action, and its
"Conversation" button opens the **main AgentOS case** of the run as soon as that case exists, instead of
staying disabled for almost every run started from the cockpit.

## 2. Acceptance criteria

From the ticket:

- **AC1**: the "Ask supervisor" button (and its "View supervisor case" link and inline error) is completely
  removed from the dashboard run cards.
- **AC2**: the "Conversation" button is labelled in English, exactly `Conversation`.
- **AC3**: clicking "Conversation" opens the main AgentOS case of the run
  (`/agentos/home?ns=<namespaceId>&case=<mainCaseId>`, new tab).
- **AC4**: factory-cockpit unit tests cover the removal of "Ask supervisor" and the activation/navigation of
  "Conversation".

Derived (flagged **[derived]**):

- **AC5 [derived]**: "Conversation" stays a disabled button only while no main case exists yet (run queued,
  first agent step not dispatched). Its tooltip says so in English.
- **AC6 [derived]**: main case resolution order (see §4.2):
  1. `controllerExecution.caseId` of the snapshot when present (parent-Run fragments: the Run root case;
     runs created with an explicit `caseId`). This keeps today's behaviour where it already works.
  2. otherwise the case of the run's **entry agent step** attempt (the step with `responsibility.kind =
     agent` and no `dependsOn`): Factory runs that step *in* the run root case
     (`CapabilityExecutionService.resolveCaseFamily`: `caseId == rootCaseId`).
  3. otherwise the case of the earliest known attempt (by `createdAt`, then `attemptNumber`).
- **AC7 [derived]**: the other card actions (Stop, Remove, Restore, Factory trace link) are unchanged.

## 4. Analysis

### 4.1 Current code

- `features/workstreams/run-card/run-card.component.{ts,html,scss,spec.ts}`: renders
  "Ask supervisor" (3 branches: link `View supervisor case`, active button, disabled button), the
  `supervisorState`/`supervisorError`/`supervisorCaseUrl` signals, a restore `effect`, the `askSupervisor()`
  handler (popup + `FactoryStore.openSupervisorCase`), `.supervisor-btn`, `.spin-icon`, `@keyframes sf-spin`
  and `.supervisor-error` styles, and `RunAction = 'ask' | 'conversation' | 'stop' | 'remove' | 'restore'`.
- Conversation: `conversationLink` getter = `buildAgentOsCaseUrl(run.controllerCaseId, run.namespaceId)`,
  disabled button otherwise.
- `features/workstreams/workstreams-page.component.ts` `onAction`: `case 'ask': case 'conversation': return`.
- `core/mappers/workflow.ts`: `controllerCaseIdOf(snapshot)` reads `snapshot.controllerExecution.caseId`;
  `mapProjectionToFactoryRun` copies it to `FactoryRun.controllerCaseId`;
  `mapProjectionToSessionDetail` copies it to `SessionDetail.controllerCaseId`;
  `mapSessionDetailToRunSummary(snapshot, detail)` builds the enriched `RunSummary`.
- `core/factory.store.ts`: cards are re-derived from the enriched detail via
  `withSummary(run, mapSessionDetailToRunSummary(snapshot, detail))` in two places (`applyWorkflows` →
  `withKnownEnrichment`, and `applyEnrichment` → `updateRun`). Attempts (`GET .../attempts`) are part of
  this enrichment for every active run.

### 4.2 Root cause of the "always disabled" Conversation button (proof)

The card only knows `controllerExecution.caseId`, which is empty for normal cockpit runs:

- `CreateWorkflowRunService.create` builds `ControllerExecutionInput(runtimeId="factory-control-plane", …,
  caseId = caseId)` where `caseId` is the optional request body field (absent from cockpit launches) →
  `controllerExecution` has no `caseId`.
- With the durable AgentOS bridge (default since the cutover), the run's root case is reserved on the
  instance (`WorkflowInstanceRecord.rootCaseId`, `CapabilityExecutionService.resolveCaseFamily`) but never
  written into `controllerExecution`. Only the legacy polling driver writes it
  (`CapabilityExecutionService.publishActiveAgentCase`).
- `WorkflowService.publicSnapshot` does not expose `rootCaseId`.

The main case id is however already available to the cockpit through the enriched attempts: the entry agent
step runs in the root case (`resolveCaseFamily`: entry step → `caseId = rootCaseId, parentCaseId = null`),
and `DurableAgentAttemptDto.caseId` is returned by `GET /api/factory/workflows/{id}/attempts`. Parent-Run
fragments keep `controllerExecution.caseId = run.rootCaseId` (`RunService.materializeFragmentWorkflowInstance`),
which stays rule 1.

Decision: resolve the main case in the frontend mapper (the ticket's "primary caseId from the run's
attempts/projection" option). Exposing `rootCaseId` in the backend snapshot would need an instance lookup per
projection in `listProjections` (N+1 on Neo4j); it is proposed as a separate ticket (§5.4).

### 4.3 Regression risk areas

- `factory.store.ts` card reconciliation (`setRuns` / `sameCardData`): a new plain string field is compared
  deeply, so stable references are kept when unchanged.
- Removed runs are never re-enriched: they keep whatever was observed while active, else rule 1 only. A
  destroyed card shows Restore only, so no visible impact.
- Specs that stub `FactoryStore` with `openSupervisorCase`/`restoreSupervisorCase` keep compiling (extra stub
  members are harmless) but should be cleaned.

## 5. Scoped change (frontend only)

### 5.1 Mapper and models (`apps/factory-cockpit/src/app/core/`)

- `models.ts`:
  - `FactoryRun`: add `mainCaseId?: string` with KDoc "AgentOS case to open from the dashboard
    Conversation button: controller case when Factory exposes one, else the run root case (entry agent step
    attempt case). Absent until the first agent step is dispatched." Keep `controllerCaseId` unchanged.
  - `RunSummary`: add `mainCaseId?: string` (same meaning, resolved from the enriched detail).
  - `SessionDetail`: add `mainCaseId?: string` (same meaning). Do not change `controllerCaseId`.
- `mappers/workflow.ts`:
  - New exported pure function
    `resolveMainCaseId(snapshot: unknown, attempts: AgentAttempt[] = []): string | undefined`:
    1. `controllerCaseIdOf(snapshot)` if non-blank;
    2. entry agent steps = projection `steps` whose `responsibility.kind === 'agent'` (use
       `classifyActorKind(step) === 'agent'` only if it is strictly equivalent; prefer reading
       `responsibility.kind`) and whose `dependsOn` is absent or empty. If **exactly one**, return the
       `caseId` of its attempt with the lowest `attemptNumber` having a non-blank `caseId`;
    3. otherwise the non-blank `caseId` of the earliest attempt (sort by `createdAt` parse, unknown last, then
       `attemptNumber`);
    4. otherwise `undefined`.
  - `mapProjectionToSessionDetail`: set `mainCaseId = resolveMainCaseId(snapshot, mappedAttempts)` with the
    same conditional-spread style as `controllerCaseId`.
  - `mapSessionDetailToRunSummary`: `if (detail.mainCaseId) summary.mainCaseId = detail.mainCaseId`.
  - `mapProjectionToFactoryRun`: `const mainCaseId = resolveMainCaseId(snapshot)`; set it when defined
    (this is rule 1 only, before enrichment).
- `mappers/index.ts`: re-export `resolveMainCaseId`.
- `factory.store.ts` `withSummary(run, summary)`: add
  `...(summary.mainCaseId ?? run.mainCaseId ? { mainCaseId: summary.mainCaseId ?? run.mainCaseId } : {})`
  (keep the object free of `undefined` keys so `sameCardData` stays stable). No other store change.

### 5.2 Run card (`features/workstreams/run-card/`)

- `run-card.component.ts`:
  - Remove `SupervisorState`, `supervisorState`, `supervisorError`, `supervisorCaseUrl`, the constructor
    `effect`, `askSupervisor()`, and the imports that become unused (`effect`, `signal`, `AgentOsApiError`,
    `SupervisorCaseResult`). Keep `inject(FactoryStore)` (used by `canStop`).
  - `RunAction` becomes `'conversation' | 'stop' | 'remove' | 'restore'` (drop `'ask'`). Keep the
    `SandboxAction` alias.
  - `conversationLink` uses `run.mainCaseId` (fallback `run.controllerCaseId` for safety) with
    `buildAgentOsCaseUrl(caseId, run.namespaceId)`. Update the KDoc (main case, resolution order) and the
    class KDoc (actions list without "Ask supervisor").
- `run-card.component.html`: delete the whole supervisor `@if/@else if/@else` block and the
  `supervisor-error` block. Keep the order Stop → Conversation → Remove. Conversation link keeps
  `target="_blank" rel="noopener"`, label `Conversation`, and gains
  `title="Open the main AgentOS case of this run"`. Disabled fallback title becomes
  `Main AgentOS case not created yet (the first agent step of this run has not started)`.
- `run-card.component.scss`: delete `.supervisor-btn`, `.spin-icon`, `@keyframes sf-spin`, `.supervisor-error`
  and the orphan comment above the media query. Check first that `sf-spin` is not referenced elsewhere in the
  cockpit (it is declared locally here; global spin uses its own keyframes).

### 5.3 Workstreams page

- `features/workstreams/workstreams-page.component.ts` `onAction`: remove `case 'ask':`; keep
  `case 'conversation': return` with a one-line comment (the card opens the link itself).

### 5.4 Out of scope (separate tickets to propose)

- Delete the now-unused supervisor infrastructure: `FactoryStore.openSupervisorCase/restoreSupervisorCase`,
  `core/supervisor-case.facade.ts` (+ spec), `core/supervisor-case-store.service.ts`,
  `core/agentos-api.service.ts`, `SupervisorCaseResult`, `buildSupervisorCaseUrl`. Left in place to keep this
  change minimal.
- Session detail page header "Conversation" (`features/session/session-page.component.html`) still uses
  `controllerCaseId`; switching it to `mainCaseId` is a one-line follow-up (not on the dashboard).
- Backend: expose the instance `rootCaseId` in the public workflow snapshot (would make the main case
  available without attempts, including for removed runs).

### 5.5 Implementation order

1. Models + `resolveMainCaseId` + mapper wiring + store `withSummary`, with mapper specs.
2. Run card cleanup + Conversation link, with run-card specs.
3. Workstreams page `onAction`, spec stubs cleanup.

## 6. Verification criteria

### 6.1 Tests to add / update

- `core/mappers.spec.ts` (`describe('resolveMainCaseId')` + mapper wiring):
  - returns `controllerExecution.caseId` when present, even when attempts exist (rule 1);
  - **fails before, passes after**: snapshot without `controllerExecution.caseId`, one entry agent step
    `plan` (no `dependsOn`) and a dependent step `build`, attempts `[{stepId:'build', caseId:'case-b'},
    {stepId:'plan', attemptNumber:1, caseId:'case-root'}]` → `mapProjectionToSessionDetail(...).mainCaseId ===
    'case-root'` and `mapSessionDetailToRunSummary(...).mainCaseId === 'case-root'`;
  - ambiguous/no entry agent step → earliest attempt by `createdAt`;
  - no controller case and no attempt → `undefined` (and `mapProjectionToFactoryRun(...).mainCaseId`
    undefined); with a controller case → `mapProjectionToFactoryRun(...).mainCaseId === controller case`.
- `features/workstreams/run-card/run-card.component.spec.ts`:
  - delete the `describe('Ask supervisor')` block and the supervisor stubs/fixtures;
  - add: no `.actions` element whose text contains `Ask supervisor` or `View supervisor case`, for a run with
    and without `namespaceId` (AC1);
  - Conversation is an `<a>` with text exactly `Conversation`, `href` `/agentos/home?ns=ns-1&case=case-main`,
    `target="_blank"` when `mainCaseId: 'case-main'` (AC2/AC3);
  - **fails before, passes after**: `mainCaseId` set and `controllerCaseId` absent → enabled link;
  - disabled button labelled `Conversation` when neither id is present (AC5); ns param omitted without
    namespace (keep existing test, adapted to `mainCaseId`).
- `core/factory.store.spec.ts`: one case where the enriched attempts give the card a `mainCaseId` while the
  snapshot has no `controllerExecution.caseId` (reuse the existing enrichment fixtures/HTTP stubs).
- `workstream-card.component.spec.ts`, `workstreams-page.component.spec.ts`: drop
  `openSupervisorCase`/`restoreSupervisorCase` from the store stubs; all assertions stay green.

### 6.2 Existing tests that must stay green

- `pnpm nx run-many -t lint test -p factory-cockpit`
- `pnpm nx run-many -t build` (at least `factory-cockpit`)

### 6.3 Neighbouring behaviours to check manually

- A freshly launched run: Conversation disabled while queued, enabled once the first agent step is
  dispatched (after the enrichment refresh), and opens the root case conversation in AgentOS.
- A Forge parent-Run fragment: Conversation opens the Run root case (unchanged).
- Stop / Remove / Restore and the "Factory trace" link behave as before; destroyed cards show Restore only.

## 7. Risk level

**Low.** Frontend-only, additive field resolved by a pure function, removal of a self-contained UI flow. The
only shared touch point is `withSummary` in the store, covered by existing card-stability tests.
