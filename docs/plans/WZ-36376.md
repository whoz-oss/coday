# WZ-36376 — [AgentOS UI] Enable agent config by default

- Jira: https://whoz.atlassian.net/browse/WZ-36376 (User Story, priority Lowest)
- Work branch: `work/forge/WZ-36376-agent-enabled-by-default`
- Base branch: `workstream/forge/master`
- Sides concerned: **frontend only** (no backend change, the API already provides everything needed)
- Risk level: **low**

## Expected outcome

A new agent config created from the AgentOS UI is enabled unless the user unticks it, and the namespace
"Agent configs" list (Namespace settings > AI > Agent configs, route `/agentos/:namespaceId/agent-configs`)
shows an "Enabled" toggle on each row that enables or disables the agent in place, without opening its form.

## Acceptance criteria

1. AC1 — On `/agentos/:namespaceId/agent-configs/new` (and `/agentos/admin/agent-configs/new`, same form),
   the "Enabled" checkbox is ticked when the form opens, and creating the agent without touching it sends
   `enabled: true`. (ticket, objective 1)
2. AC2 — The user can still untick it before creation, which sends `enabled: false`. (derived)
3. AC3 — In edit mode the checkbox keeps reflecting the stored value (`enabled ?? true`, unchanged), so a
   disabled agent opens unticked. (derived — regression guard)
4. AC4 — The namespace agent-configs table has an "Enabled" column. Each namespace-scoped row has a
   toggle reflecting `config.enabled`; changing it enables or disables that agent through the API and the row
   reflects the server's answer. (ticket, objective 2)
5. AC5 — Platform-scoped rows (read-only in this page) show their state as a tag (`Enabled` / `Disabled`)
   and offer no toggle, consistent with the existing "Read-only" handling of platform rows. (derived)
6. AC6 — While a toggle request is in flight the row's toggle is disabled; on failure the toggle goes back
   to its previous state and an error is shown in the existing `settings-table__error` alert. (derived)
7. AC7 — The table filter also matches "Enabled" / "Disabled", like the scheduled-prompt lists. (derived)

## Analysis (current state, with proof)

- **Default off on create** — `libs/agentos-ui/src/lib/components/agent-config-form/agent-config-form.component.ts`,
  form definition: `enabled: new FormControl<boolean>(false, { nonNullable: true })`. In create mode
  (`ngOnInit` → `loadIntegrations`) nothing overrides it, and `submit()` sends `enabled: this.enabledControl.value`,
  so a new agent is persisted disabled. Edit mode hydrates with `config.enabled ?? true` (unchanged by this plan).
- **Backend default** — `agentos/agentos-service/src/main/kotlin/io/whozoss/agentos/agentConfig/AgentConfigController.kt`,
  `toDomain`: `enabled = resource.enabled ?: false`. The UI always sends the field explicitly, so the UI change
  is enough. Changing the API default would alter the contract for every API/SDK client and is out of scope.
- **Toggle endpoints already exist** — `POST /api/agent-configs/{id}/enable` and `POST /api/agent-configs/{id}/disable`
  (`AgentConfigController.enable/disable`, `@PreAuthorize(... 'AgentConfig', 'WRITE')`), both returning the
  updated `AgentConfigDto`. Generated client: `AgentConfigControllerService.enableAgentConfig(id)` /
  `disableAgentConfig(id)` in `libs/agentos-api-client/src/lib/api/agent-config-controller.service.ts`.
  Note: `AgentConfigServiceImpl.disable` also disables the scheduled prompts bound to the agent (existing
  server-side behaviour, desired: a disabled agent cannot run them anyway).
- **List page** — `libs/agentos-ui/src/lib/components/namespace-agent-configs/namespace-agent-configs.component.{ts,html}`.
  Loads `listByParentAgentConfig(namespaceId)` (default `withDisabled=true`, so disabled namespace agents are
  listed) and `listPlatformAgentsAgentConfig()` (default `withDisabled=false`, platform rows are therefore
  always enabled ones). Rows are `{ key, config, scope }` in a `rows` signal; no spec file exists for it.
- Design system has no switch component; the checkbox idiom is `<label dsCheck><input type="checkbox"/>`
  (`libs/design-system/src/lib/components/check/check.directive.ts`), state tags use `ds-tag`
  (`accent` = Enabled, `outline` = Disabled, as in `scheduled-prompt-list.component.html`).
- Recent history of the list files: UI redesign/filters (`ee12ee2c`, `7cab63a5`, `e17f7f82`, `cbc8b16f`) —
  keep the `settings-table__*` classes and the `rowFilter` / `deletion` utilities as they are.

## Scoped change

### Frontend

1. `libs/agentos-ui/src/lib/components/agent-config-form/agent-config-form.component.ts`
   - Change the initial value of the `enabled` control from `false` to `true`. Nothing else: the edit-mode
     hydration (`config.enabled ?? true`) and the submit payload stay as they are.
   - Template `agent-config-form.component.html`: no change required (checkbox already bound to
     `enabledControl`). Optionally keep the hint text as is.

2. `libs/agentos-ui/src/lib/components/namespace-agent-configs/namespace-agent-configs.component.ts`
   - Add a `togglingKey = signal<string | null>(null)` (or a `Set` signal) for the in-flight row, and a
     `toggleError = signal<string | null>(null)`.
   - Add `protected toggleEnabled(row: AgentConfigRow): void`:
     - return early if `row.scope === 'platform'`, `!row.config.id`, or a toggle is already in flight for the row;
     - call `controller.disableAgentConfig(id)` when `row.config.enabled` is true, otherwise
       `controller.enableAgentConfig(id)`, piped through `takeUntilDestroyed(this.destroyRef)`;
     - on success replace the row's `config` with the returned `AgentConfig` in `rows` (same pattern as
       `ScheduledPromptListComponent.toggle`), clear the in-flight marker;
     - on error clear the in-flight marker, leave the row unchanged (the checkbox is bound with
       `[checked]="row.config.enabled"`, so the view reverts on the next change detection — make sure it does,
       e.g. by re-setting `rows` with a new array/row object, because the native checkbox has already flipped),
       and set `toggleError` to `` `${row.config.enabled ? 'Disabling' : 'Enabling'} "${row.config.name}" failed. Try again.` ``.
     - clear `toggleError` at the start of each toggle.
   - Extend the `rowFilter` text with `row.config.enabled ? 'Enabled' : 'Disabled'`.
   - Treat `enabled` as `config.enabled === true` for display (the DTO marks it optional).

3. `libs/agentos-ui/src/lib/components/namespace-agent-configs/namespace-agent-configs.component.html`
   - Add an `<th role="columnheader">Enabled</th>` column (after "Execution mode", before "Scope").
   - Cell `data-label="Enabled"`:
     - namespace row: `<label dsCheck><input type="checkbox" role="switch" [checked]="row.config.enabled === true"
       [disabled]="isToggling(row)" [attr.aria-label]="'Enabled: ' + row.config.name" (change)="toggleEnabled(row)" /></label>`
       (import `CheckDirective` from `@whoz-oss/design-system` into the component `imports`);
     - platform row: `<ds-tag [variant]="row.config.enabled ? 'accent' : 'outline'">Enabled|Disabled</ds-tag>`.
   - Show `toggleError()` in a `<p class="settings-table__error" role="alert">` next to the existing deletion error.
   - Hide the toggle while the row is in delete-confirmation (`deletion.confirmingId() === row.key`) is not
     required; keep it simple and always show it.

### Backend

No change. Contract used (existing, unchanged):

- `POST /api/agent-configs/{id}/enable` → `200 AgentConfigDto` (with `enabled: true`)
- `POST /api/agent-configs/{id}/disable` → `200 AgentConfigDto` (with `enabled: false`; also disables the
  agent's scheduled prompts server-side)
- Both require `WRITE` on the agent config (namespace admin); a 403 surfaces through the error path of AC6.
- `POST /api/agent-configs` body field `enabled: boolean` — the form now sends `true` by default.

Implementation order: form default (1), then list component (2, 3), then tests.
