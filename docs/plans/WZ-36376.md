# WZ-36376 — [AgentOS UI] Enable agent config by default — follow-up: Enabled checkbox corrections

- Jira: https://whoz.atlassian.net/browse/WZ-36376 (User Story, priority Lowest)
- Work branch: `work/forge/WZ-36376-enabled-toggle-label`
- Base branch: `workstream/forge/master` (at `e2d14873`)
- Previous delivery: PR #1767 (`work/forge/WZ-36376-agent-enabled-by-default`), merged into the workstream on
  2026-11-25. It made new agents enabled by default and added the Enabled column. This plan only covers the two
  corrections asked afterwards in the Jira comment of 2026-11-27 (Barthelemy Bidot).
- Sides concerned: **frontend only**
- Risk level: **low**

## Expected outcome

On Namespace > AI > Agent configs (`/agentos/:namespaceId/agent-configs`), every row shows an "Enabled"
checkbox with the visible text "Enabled" next to it: namespace agents keep their working toggle, platform agents
show a checkbox that is ticked and locked (disabled) instead of the current `Enabled` / `Disabled` tag.

## Acceptance criteria

1. AC1 — Each platform-scoped row shows, in the Enabled column, a checkbox that is ticked and disabled (the user
   cannot change it), instead of the `ds-tag`. Clicking it never calls `enableAgentConfig` / `disableAgentConfig`.
   (Jira comment, point 1)
2. AC2 — Each namespace-scoped row shows the visible text "Enabled" next to its checkbox, inside the same
   `label[dsCheck]` (so clicking the text toggles the box). (Jira comment, point 2 + screenshot)
3. AC3 — The namespace toggle behaviour delivered by PR #1767 is unchanged: state reflects `config.enabled`,
   it calls `/enable` or `/disable`, all switches are disabled while a request is in flight, a failure restores the
   previous state and shows the alert, the alert is cleared at the next toggle. (derived — regression guard)
4. AC4 — The platform locked checkbox carries the same "Enabled" text, for a consistent column. (derived: the
   comment asks for the checkbox on both kinds of rows; showing the label on one only would look broken)
5. AC5 — The filter keeps matching "Enabled" / "Disabled" (unchanged). (derived)
6. AC6 — The agent creation form still defaults to enabled (unchanged since #1767). (derived — regression guard)

## Analysis (current state, with proof)

- `libs/agentos-ui/src/lib/components/namespace-agent-configs/namespace-agent-configs.component.html`, cell
  `td[data-label="Enabled"]`:
  - namespace branch: `<label dsCheck><input #enabledInput type="checkbox" role="switch" ... /></label>` with
    **no text** inside the label → point 2 of the comment;
  - `@else` (platform) branch: `<ds-tag [variant]="isEnabled(row) ? 'accent' : 'outline'">Enabled|Disabled</ds-tag>`
    → point 1 asks for a ticked, locked checkbox instead.
- `dsCheck` (`libs/design-system/src/lib/components/check/check.directive.ts`) is designed for
  `<label dsCheck><input type="checkbox" /> Text</label>`; `.ds-check` in
  `libs/design-system/src/styles/_primitives.scss` already lays out input + text (inline-flex, gap 0.5rem). No
  style change needed. The native `:disabled` look is enough for "locked".
- Platform rows come from `listPlatformAgentsAgentConfig()` called without `withDisabled` (server default
  `false`), so every platform row on this page is an enabled agent: binding `[checked]="isEnabled(row)"` renders
  it ticked, as requested, while staying truthful if the API ever returns a disabled one.
- `namespace-agent-configs.component.ts`: `toggleEnabled()` already returns early (and resets the box) for
  platform rows; nothing to change in the class.
- Existing spec `namespace-agent-configs.component.spec.ts` (added by #1767) has the test
  "shows a platform agent as a read-only tag, with no switch", which asserts the old behaviour and must be
  rewritten. Its other tests select namespace switches by `input[role="switch"][aria-label="Enabled: <name>"]`.

## Scoped change

### Frontend

1. `libs/agentos-ui/src/lib/components/namespace-agent-configs/namespace-agent-configs.component.html` — cell
   `td[data-label="Enabled"]` only:
   - namespace branch: keep the input exactly as it is (same bindings, `role="switch"`, `aria-label`,
     `#enabledInput`, `(change)`), and add the text `Enabled` after the `<input />`, inside the `<label dsCheck>`.
   - platform branch: replace the `ds-tag` with
     ```html
     <label dsCheck>
       <input
         type="checkbox"
         [checked]="isEnabled(row)"
         disabled
         [attr.aria-label]="'Enabled: ' + row.config.name"
       />
       Enabled
     </label>
     ```
     No `role="switch"` and no `(change)` handler: it is a locked indicator, not a control. (Keeping it out of the
     `role="switch"` selector also keeps the namespace-only test selectors meaningful.)
   - Nothing else in the template changes (header, Scope tags incl. "Read-only", actions, alerts).
2. `namespace-agent-configs.component.ts`: **no change** expected. If `TagComponent` becomes unused in the
   template, keep it in `imports` — it is still used by the Scope column.

### Backend

No change. Existing contract still used by the namespace toggle: `POST /api/agent-configs/{id}/enable` and
`POST /api/agent-configs/{id}/disable`, each returning the updated `AgentConfig`.
