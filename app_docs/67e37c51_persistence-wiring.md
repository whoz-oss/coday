# Persistence barrel and operational wiring

The Factory persistence surface now exposes the scheduling, worker-liveness, and lease repositories alongside the existing persistence adapters. This makes the three SQL implementations reachable through the normal TypeScript barrels and through the generated operational runtime.

## What changed

- `factory/src/ports/persistence/index.ts` now exports the `WorkUnitRepository`, `WorkerRepository`, and `LeaseRepository` type surfaces, including their scopes, filters, and lease operation option/result types.
- `factory/src/adapters/persistence/sql/index.ts` now exports `SqlWorkUnitRepository`, `SqlWorkerRepository`, and `SqlLeaseRepository`, their `createSql*Repository` factories, the work-unit and worker SQL error classes, and the corresponding options types.
- `factory/src/adapters/persistence/index.ts` re-exports those SQL classes, factories, error classes, and options from the SQL barrel, preserving the top-level persistence adapter surface.
- `factory/tests/test-sql-repository-ports-adapters.mjs` imports the three new SQL classes/factories and adds `work-unit`, `worker`, and `lease` to the global wiring matrix. The matrix now covers twelve ports. SQL-only entries omit a filesystem adapter; their checks still require an exported constructor, a working factory that instantiates the same class, and a non-empty public prototype. Filesystem-vs-SQL method parity remains enforced for the nine ports that have filesystem implementations.
- `factory/runtime/factory-operational.mjs` was regenerated by the build toolchain. The generated runtime now contains the work-unit, worker, and lease domain/SQL implementation code and exports the newly wired symbols; it was not hand-edited.
- `specs/67e37c51_persistence_barrels_global_wiring.md` records the implementation plan, touched-file matrix, wiring details, regeneration command, verification commands, and scope constraints.

## How to verify

From the repository root, run:

```bash
node factory/tests/test-sql-repository-ports-adapters.mjs
node factory/tests/test-conformance-workunit-worker.mjs
node factory/tests/test-lease-protocol.mjs
```

The first command is the global offline wiring/contract gate. It uses the in-memory SQL client, so it does not require PostgreSQL or Docker, and checks all twelve descriptors. Related repository tests listed by the implementation plan can also be run with:

```bash
node factory/tests/test-repository-ports-adapters.mjs
node factory/tests/test-sql-unit-of-work.mjs
```

If the generated runtime needs to be refreshed after source changes, use the prescribed build entry point rather than editing the bundle directly:

```bash
node factory/toolchain/build.mjs
```
