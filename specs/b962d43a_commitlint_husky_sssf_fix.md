# Execution Plan - Commitlint & Husky SSSF Factory Fix

## Diagnostic Analysis

### Context & Issue
During automated Software Factory / ADW runs, commit steps (`commit_plan`, `commit_build`, `commit`, `commit_docs`) frequently fail during git commit execution when Husky's `commit-msg` hook executes `commitlint`.
These automated commits are produced by AI agents or workflow automation scripts and frequently trigger commitlint validation failures due to default strict conventional commit rules:
1. `header-max-length`: Default standard rule enforces max 100 characters. AI-generated subject headers routinely exceed 100 characters (e.g. 105-120 chars).
2. `body-max-line-length`: Default rule enforces max 100 characters per line in the commit body. AI multi-line explanation bodies routinely contain long paragraph lines (>100 chars).
3. `subject-case`: Default rule requires `lower-case` subject headers (rejecting sentence-case or PascalCase/upper-case subjects such as `feat(plan): Add plan for...` or `fix(builder): Fix bug...`).

### Scope & Constraints
- Modify root `commitlint.config.ts` and/or `.husky/commit-msg` only.
- Do NOT touch `factory/**` or `agentos/**`.
- Do NOT globally disable conventional commit validation for human commits or degrade quality standards.

## Proposed Solution & Strategy

### 1. Relax Restrictive Project Commitlint Rules (`commitlint.config.ts`)
Update root `commitlint.config.ts` to export rules that accommodate both human developer workflows and LLM agent output patterns without disabling structural conventional commit type/scope checking:
- `'header-max-length'`: Increase from default 100 to `[2, 'always', 120]`. (Matches Coday's codebase line length standard of 120 characters).
- `'body-max-line-length'`: Set to `[0]` (disabled) so detailed multi-line commit bodies with long links, error logs, or explanations do not fail linting.
- `'footer-max-line-length'`: Set to `[0]` (disabled) for consistency with long footer references/trailers.
- `'subject-case'`: Set to `[0]` (disabled rule `[0]`) so sentence-case (`Add feature...`), lower-case (`add feature...`), and mixed-case subjects generated by agents pass validation smoothly.

### 2. SSSF / Agent Automated Commit Bypass in Husky (`.husky/commit-msg`)
Update `.husky/commit-msg` to check environment variables and git author credentials prior to calling commitlint:
- Check for presence of SSSF / ADW / Factory automation flags or environment variables:
  - `SSSF_*` env vars (e.g. `SSSF_AUTOMATED_COMMIT`, `SSSF_RUN_ID`, `SSSF_PHASE`, `SSSF_AGENT_NAME`, etc.)
  - `GIT_AUTHOR_NAME` or `GIT_COMMITTER_NAME` matching SSSF/Factory patterns (e.g. contains `SSSF`, `factory`, `adw`, `bot`, or `agent`).
  - Standard CI/bypass environment variables (e.g. `COMMITLINT_SKIP=1`, `SKIP_COMMITLINT=1`, `NO_HOOKS=1`, `CI=true`).
- If an automated commit is detected via environment variables or author identity, skip `commitlint` validation (or log a message and exit 0).
- For all standard interactive / human developer commits, continue executing `npx --no -- commitlint --edit $1`.

### 3. Automated Test Suite / CLI Verification
Create unit test / script verification for commitlint rules using Jest or a dedicated commitlint CLI test script to ensure:
- Standard conventional human commits (`feat(ui): add button component`) pass.
- Agent header formats with length up to 120 chars pass.
- Agent sentence-case headers (`feat(builder): Implement fix for...`) pass.
- Multi-line agent commit bodies with lines >100 chars pass.
- Invalid non-conventional types (`foo: bar`) continue to fail.

## Proposed Changes

### Configuration Updates

#### `commitlint.config.ts`
```typescript
import type { UserConfig } from '@commitlint/types'

const Configuration: UserConfig = {
  extends: ['@commitlint/config-conventional'],
  rules: {
    'header-max-length': [2, 'always', 120],
    'body-max-line-length': [0],
    'footer-max-line-length': [0],
    'subject-case': [0],
  },
}

export default Configuration
```

#### `.husky/commit-msg`
```bash
#!/bin/sh

# Bypass commitlint validation for automated SSSF / Factory / Agent commits
if [ -n "$SSSF_AUTOMATED_COMMIT" ] || \
   [ -n "$SSSF_RUN_ID" ] || \
   [ -n "$SSSF_PHASE" ] || \
   [ -n "$COMMITLINT_SKIP" ] || \
   [ -n "$SKIP_COMMITLINT" ] || \
   echo "$GIT_AUTHOR_NAME $GIT_COMMITTER_NAME" | grep -qiE '(sssf|factory|coday-bot|agent)'; then
  exit 0
fi

npx --no -- commitlint --edit $1
```
